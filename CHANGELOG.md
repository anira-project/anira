- **ABI (unstable):** `anira/abi/tensor.h`, the runtime tensor of section 1 (ABI 0.2; 150 promised names). Three Tier-1 records, frozen with no `struct_size` and no version field, identical on wasm32, LP64 and LLP64: `anira_tensor` (216 bytes: `domain`, `dtype`, `ndim`, `flags`, `shape[8]`, `strides[8]` in elements with all-zero = packed row-major, `byte_offset`, `handle`, `manager_ctx`, `release`, `acquire`), the union `anira_memory_handle` (24 bytes, the thirteen arms `host`, `cuda`, `gl`, `vk`, `opaque`, `mtl`, `iosurface`, `wgpu`, `dmabuf`, `ahb`, `d3d12`, `planes`, `raw[3]`, every vendor handle at its wire width) and `anira_sync_token` (24 bytes: `kind`, `flags`, the payload union `u`), with the release callback `anira_tensor_release_proc`, a function type that sits in an `ANIRA_PTR` slot (`[thread-safe, !audio-thread]`, not real-time: it runs on an inference thread or on the caller of poll / wait / prepare / destroy, never on the driver thread). The factories `anira_tensor_init_host` / `pinned` / `cuda` / `gl_buffer` / `vulkan` / `opaque_fd` / `wgpu_buffer` / `dmabuf` zero the caller's record and then fill it, `[thread-safe]` `[callback-safe]` `ANIRA_NONBLOCKING`, and return nothing: a dtype of 0, a rank above `ANIRA_MAX_RANK`, a NULL shape with a rank above 0 or a negative extent leave the record all-zero, which no filled record is; every argument is read before the record is zeroed, so `shape` and a token may point into the record being filled (`anira_tensor_init_host(&t, p, t.dtype, t.ndim, t.shape)` re-points a tensor), and the previous content is overwritten, never released; a NULL fence, a timeline semaphore of 0 and a negative `sync_fd` mean `ANIRA_SYNC_NONE` (anira never fabricates a fence), a token passed by pointer is copied and that copy is the hand-off, a `sync_fd` of 0 or more is owned by the record's `acquire` from there on, and a refused call takes neither the token nor the fd. Planar host memory is part of the tensor, contained: `ANIRA_TENSOR_PLANAR = 8` is appended to `anira_tensor_flags`, the `planes` arm holds `ptrs`, `count` and `reserved`, `anira_tensor_init_host_planar(tensor, planes, count, dtype, ndim, shape)` fills it from one pointer per plane of axis 0 (the channel pointers of an audio host; `planes` is `const void*`, so a `float**` and a `const float* const*` convert without a cast in C and in C++; `count` must equal `shape[0]` and the rank be 1 or more, else the record stays all-zero) and `anira_tensor_plane(tensor, plane, dtype)` reads one plane with `byte_offset` applied. It is a boundary representation of the two host domains: only an entry whose own documentation says so accepts a planar tensor, every other consumer and every other domain refuses the flag with `ANIRA_ERROR_NOT_SUPPORTED`, and `anira_tensor_data` / `anira_tensor_data_f32` return NULL for one. `anira_tensor_init_dlpack(tensor, dl_managed_tensor_versioned, err)` (`[main-thread]`; `anira_error*` last, which the design document's sketch lacks) bridges a DLPack 1.x `DLManagedTensorVersioned` handed over as `void*`: `kDLCPU` is `ANIRA_DOMAIN_HOST`, `kDLCUDAHost` `ANIRA_DOMAIN_HOST_PINNED`, every other device and every dtype code above 6 `ANIRA_ERROR_NOT_SUPPORTED`, as is a major other than 1 (nothing past the version is read); shape and strides are copied (NULL strides = packed row-major; strides that are present and all zero over more than one element, a fully broadcast view, are `ANIRA_ERROR_NOT_SUPPORTED`, because all-zero is this record's spelling of packed), `DLPACK_FLAG_BITMASK_READ_ONLY` sets `ANIRA_TENSOR_READ_ONLY`, `release` is a trampoline that disarms the record and calls the producer's deleter exactly once (a NULL deleter is a borrowed tensor); a refused call leaves `*tensor` untouched and never calls the deleter. The accessors `anira_tensor_data_f32` (host and pinned float32 only, `byte_offset` honoured, NULL otherwise), `anira_tensor_data(tensor, dtype)` (NULL unless `dtype` is the tensor's own; never converts), `anira_tensor_num_elements` (1 at rank 0, 0 with a zero extent and for the dtype-0 record of a refused factory) and `anira_tensor_extent` (0 at and beyond `ndim`), and `anira_sizeof(anira_struct_id)` for allocators that cannot see the header: every record the headers define answers (eleven, `ANIRA_STRUCT_STAGE_CTX` of `anira/abi/stage.h` among them), every unknown id returns 0. `anira_sync_token_reset` / `anira_sync_token_dup` (`[thread-safe, !audio-thread]`: closing and duplicating are system calls) end and duplicate the descriptor of the two owning fd kinds, a plain zero and a plain copy for every other kind: an fd of 0 or more on POSIX (`close`, and a close-on-exec duplicate), an NT handle above 0 on Windows (`CloseHandle`, `DuplicateHandle`), nothing on WebAssembly, where reset closes nothing and a duplicate of an owning kind is `ANIRA_ERROR_NOT_SUPPORTED`. Tests: `test_Tensor` (`AbiTensor`, `AbiTensorSync`, `AbiTensorDlpack`: zero-then-fill of all thirteen factories byte for byte, the planar tensor, the NULL rules, fd ownership over a pipe, the bridge over the tests' own spelling of dlpack.h in `test/abi/dlpack_producer.h`) in `test_abi`; gate 3 pins 216/24/24 and every offset through the union arms, gate 4 covers the header from C11, C++17 and alone.
- **ABI (unstable):** the Hard entries over host tensors, under the bare names of `anira/abi/handler.h`, which includes `anira/abi/tensor.h` now (ABI 0.2; 160 promised names): `anira_handler_process(handler, in, in_slot, out, out_slot, delivered)`, `anira_handler_process_multi(handler, inputs, num_inputs, outputs, num_outputs, delivered)`, `anira_handler_push_data(handler, in, slot)`, `anira_handler_push_data_multi(handler, inputs, num_inputs)`, `anira_handler_pop_data(handler, out, slot, delivered)`, `anira_handler_pop_data_multi(handler, outputs, num_outputs, delivered)` (`[driver-thread]`, `ANIRA_NONBLOCKING`) and the four `_wait` twins `anira_handler_process_wait`, `process_multi_wait`, `pop_data_wait`, `pop_data_multi_wait` (`[any-thread, blocking]`; a `_wait` twin is its bare form with `double timeout_ms` appended as the last parameter: `anira_handler_process_wait(handler, in, in_slot, out, out_slot, delivered, timeout_ms)`, `anira_handler_pop_data_wait(handler, out, slot, delivered, timeout_ms)`, and likewise the two multi forms). A host block is one `const anira_tensor*` per slot, an output's included: a descriptor is never written, the memory it names is, so a host builds its tensors once and reuses them. The logical shape is `[channels, samples]` (`[1, values]` for a Static slot), the sample count is `shape[1]` (no `num_in` / `num_out`), and the memory is planar (`ANIRA_TENSOR_PLANAR`: these are the entries that accept the flag), one block read by `strides` (contiguous `{samples, 1}`, interleaved `{1, channels}`) or one packed block (all-zero strides), for any channel count; the two sides of a call may be described differently, and one tensor handed over as input and output is in place (there is no `_inplace` name). The tensor's dtype must be the slot's (the ring dtype of a Streamed slot): nothing converts, and another dtype is `ANIRA_ERROR_CONFIG`. A malformed descriptor is `ANIRA_ERROR_INVALID_ARGUMENT` (a rank other than 2, which includes the zeroed record a refused factory leaves, a domain other than `ANIRA_DOMAIN_HOST` and `ANIRA_DOMAIN_HOST_PINNED`, `ANIRA_TENSOR_READ_ONLY` on an output, `shape[0]` other than the slot's channel count, a negative `shape[1]`, and with samples: NULL memory, a plane count other than `shape[0]`, a NULL plane, a negative stride, a stride of 0 on an axis longer than 1 unless every stride is 0, a channel that does not start on a multiple of the element size), a flag bit this library does not know is `ANIRA_ERROR_NOT_SUPPORTED`, and the check order is fixed: rank, domain, flags, shape, dtype, memory and strides, the input before the output. Every tensor of a call is validated before anything is pushed, so a refusal writes no ring. An empty tensor (`shape[1] == 0`; its memory arm is not read, NULL is legal) leaves a slot out; the multi forms take exactly one tensor per slot, Static slots included, and refuse another `num_inputs` / `num_outputs` with `ANIRA_ERROR_INVALID_ARGUMENT`. `delivered`, single and multi, is a nullable pure out parameter written on every return: zeroed first, then `shape[1]` of each output on `ANIRA_OK` (clamped to the tensor's size for a Static output), 0 on `ANIRA_MISSED` and on a failure, and on the `ANIRA_ERROR_INVALID_STATE` of a `_wait` twin what the nonblocking stem delivered. It is never read: the request is `shape[1]` of each output tensor, so a miss leaves nothing to refill. `release`, `manager_ctx` and `acquire` are not read: the memory is borrowed until the call returns. There is no float-only family of entries: a host that holds channel pointers builds one planar tensor over its pointer array with `anira_tensor_init_host_planar`, once, and stores `shape[1]` before each call. `anira_handler_rt_error` latches one more kind, `ANIRA_ERROR_NOT_SUPPORTED` (`anira::RtKind::NotSupported`). Tests: `test_HandlerTensor` (`AbiHandlerTensor`) in `test_abi`: every description against absolute expectations (each channel its own ramp, late by the reported latency) for 1, 2, 3 and 6 channels, crossed descriptions, in place, the multi forms with a Static slot and the clamped count, the single forms beside unused slots, the three miss policies, every refusal with its status, its latched record and the check order, and every descriptor compared byte for byte around its call; the named comparisons that stand in for one oracle (the entries and the 2.x handler share the copy path, and a pass-through cancels a symmetric stride bug): a white-box look at the send ring after `anira_handler_push_data` under every description, a planar against an interleaved description over one script with missed blocks under the three policies, bit for bit, and an interleaved stereo block with the Static gain as `[1, 1]` through `anira_handler_process_multi` against the 2.x `anira::InferenceHandler` in one binary on the bundled stereo gain model (`stereo_gain_with_custom()`), on every plan this build has an engine for and on the custom row (through a real engine that covers two channels; three and six channels run through the engine-free pass-through); `test_Prepare` runs its miss sequence over planar and over packed tensors, under `ANIRA_MISS_CALLBACK` too, `test_HandlerWait` drives the four tensor twins (a deadline is `ANIRA_MISSED`, `ANIRA_WAIT_FOREVER` delivers); `test_rt_contract.c` calls the six nonblocking entries from an `ANIRA_NONBLOCKING` function, `header_c.c` and `header_cxx17.cpp` call one.
- **ABI (unstable):** the fourth miss policy, `ANIRA_MISS_CALLBACK = 3` (appended to `anira_miss_policy`; `"on_miss": "callback"` in a contract file), with the backup function `anira_miss_fn` and its setter `anira_contract_hard_set_miss_fn(contract, fn, user_data)` in `anira/abi/config.h`, which includes `anira/abi/tensor.h` now (`[main-thread]`; `ANIRA_ERROR_WRONG_CONTRACT` on an Async contract, `ANIRA_ERROR_INVALID_ARGUMENT` for a NULL contract, a NULL `fn` clears the pair; 161 promised names). `typedef anira_status (ANIRA_CALL* anira_miss_fn)(anira_handler* handler, const anira_tensor* inputs, uint32_t num_inputs, const anira_tensor* outputs, uint32_t num_outputs, void* user_data) ANIRA_NONBLOCKING;` is the first `ANIRA_NONBLOCKING` function-pointer typedef of the ABI (`[driver-thread]`; a `_wait` twin calls it on the waiting thread). It fills a whole missed block, every slot at once and whatever the slots' dtypes: one call per missed block on the thread that called the entry, with the very arrays the copy path was handed, so nothing is built on a miss: the caller's own tensors under a tensor entry (a single-tensor form on a side with several slots passes the handler's array: the caller's descriptor in its slot, empty tensors beside it, which name no memory, since a staged slot is the empty tensor of prepare again when its call returns and no pointer of an earlier call stays in it), and empty inputs in a pop. The input block of a process form is already pushed and still intact in host memory, in place too. `ANIRA_OK` means the outputs are filled; any other status makes anira zero-fill every requested output. Either way the block counts as missed: the entry returns `ANIRA_MISSED` with a delivered count of 0 and the stream stays time-aligned, and a `_wait` twin without an inference thread still returns `ANIRA_ERROR_INVALID_STATE`, after the function ran. The function must not call a Hard entry, `anira_handler_reset` or `anira_handler_prepare` of the same handler, and under clang a function converted to `anira_miss_fn` must itself be declared `ANIRA_NONBLOCKING`. The two setters work in either order; the policy without a function is `ANIRA_ERROR_CONFIG` at `anira_handler_prepare`, naming `on_miss` (that is where a contract parsed from a file, which cannot carry a function, is caught: set the pair on the parsed contract first); the pair is copied with the contract and must outlive the prepared handler. Prepare also refuses `ANIRA_MISS_BYPASS` when a streamed output's ring dtype differs from the anchored input's (it cannot fire while every ring is float32). Scheduler: `InferenceManager::set_miss_hook(hook, ctx)` and a `case ANIRA_MISS_CALLBACK` in the starvation path of `process_output`, called once before the per-output fill; the accounting of a missed block is the same under every policy. Tests: `AbiHandlerTensorMiss` in `test_HandlerTensor` (the function declared `ANIRA_NONBLOCKING`, no assertion inside it; an allocation planted in it is reported by RealtimeSanitizer through `anira_handler_process`), `test_Json`, `test_Handles`, `test_anira_hpp`; `test_rt_contract.c` holds a nonblocking `anira_miss_fn` body that reads and fills its tensors through the `[callback-safe]` accessors and hands it to the setter, so `-Werror=function-effects` proves the conversion clean.

On the inference thread the stage processor binds the model's State input to the read buffer (the state the last inference produced) and the model's State output of the pair to the write buffer as the first step of an inference, ahead of the stage's `before_inference` (which sees the read side through `anira_stage_input_tensor` and may read or alter it), and flips the pair as the last step, behind the stage's `after_inference` (which sees the write side through `anira_stage_output_tensor`): what an inference wrote is what the next one reads, and anira copies nothing (the engine binds the two buffers as it binds every slot: ONNX Runtime in place both ways, LibTorch's input in place and its result copied out, ExecuTorch, TFLite and LiteRT copied both ways, a registered engine as its prepare bound them; the 2.x `BackendBase` of the `anira.v2.custom` row gets them copied into its buffers and out). Both steps are field fills without an allocation or a lock. A failed inference (an engine failure, a non-OK `before_inference` or `after_inference`) does not flip, so the read side keeps the last good state; a dropped chunk never runs and does not advance it. The state is the handler's and not a session's or a processor's, so it survives `anira_handler_set_plan`. A State spec may stand anywhere in the inputs list and in the outputs list, so the lists follow the model file's own tensor order. Validation, at `anira_handler_create` and again at `anira_handler_prepare`, `ANIRA_ERROR_CONFIG` naming the tensor: a State input without a source; a source that names no output, or an output of another role; a State output named by no State input, or by two; a source on an output spec or on a spec of another role; two halves of unequal dtype or shape; a Time axis, a window, a time ratio or a latency on a State spec; a ring dtype or the anchor naming one. `ANIRA_ERROR_NOT_SUPPORTED` in this pre-release: a transposed layout on a State spec (a view layout prepares). A pair of another dtype than float32 is legal (its buffers never travel through the queue, whose storage is float32 in this pre-release): a registered engine binds what its prepare accepts (an int32 pair runs), a built-in adapter refuses it at prepare with `ANIRA_ERROR_CONFIG` naming the engine and the tensor. A Channel axis of any extent is legal, as on every non-Streamed spec. Initial values other than zeros and host-readable state are not part of this pre-release. `test/abi/test_State.cpp` runs the engine-free twin of the example models' `StatefulAccumulatorNetwork` against its closed form, the same accumulator as a registered C engine (the pointer identity of the two buffers through a stage's hooks, a failed inference that does not promote, a reset that zeroes the read side alone, the state surviving a plan switch between two registered engines, an int32 pair) and the bundled file on every engine of the build (the pointer identity on each, the closed form, and on ONNX Runtime the pair bound by name under other canonical names).

### Changed

- **Breaking (ABI, unstable):** `anira_stage_phase` is renumbered so the three inference-thread phases count in the order they run: `ANIRA_PHASE_INFERENCE` takes 3, `ANIRA_PHASE_AFTER_INFERENCE` moves 3 -> 4, `ANIRA_PHASE_PREPARE` 4 -> 5, `ANIRA_PHASE_RELEASE` 5 -> 6 (`PRE_PROCESS` 0, `POST_PROCESS` 1 and `BEFORE_INFERENCE` 2 stay). Migration: recompile against the new `anira/abi/enums.h` (and take `web/src/abi/enums.ts` with it); use the names, never the numbers. No entry point consumes the enum yet, so no stored value exists.
- **Design (docs/anira-v3-architecture.md, `anira/anira.hpp`):** a custom engine is part of the inference stage, never a stage of its own. It is one more implementation the stage's candidates resolve to (`anira_pipeline_register_engine`, a later pre-release; legal before or after `anira_pipeline_add_inference`), it takes no place beside the pipeline's stage, and its `process` runs in `ANIRA_PHASE_INFERENCE`. - **Breaking (2.x classes):** `ANIRA_REALTIME` is gone. The eight real-time declarations of `anira::InferenceHandler` (`process`, `push_data`, `pop_data`, `reset`) carry `ANIRA_NONBLOCKING` of `anira/abi/export.h` — clang's `nonblocking` attribute wherever clang has it, no longer gated on `ANIRA_WITH_RTSAN` — and `anira/utils/RealtimeSanitizer.h` keeps `ANIRA_BLOCKING` alone. - The three miss policies are implemented in the scheduler's starvation path, so the `ANIRA_MISS_BYPASS` default of `anira_contract_create_hard`, of `anira::Hard{}` and of the bundled contract files is truthful from here: `ANIRA_MISS_ZEROS` delivers zeros (the 2.x behaviour), `ANIRA_MISS_HOLD_LAST` repeats the last delivered block of every streamed output (one block-sized buffer per output channel, allocated at prepare) and the latest value of a Static output, `ANIRA_MISS_BYPASS` copies the block the call pushed into the anchored input into the output on the process forms (the smaller of the input's and the output's sample count, zeros past the input; a call that pushed another slot, and a pop, deliver zeros). A missed block returns `ANIRA_MISSED` under every policy, with every delivered count 0 (the policy governs the buffer's content, the status says the block was missed), the stream stays time-aligned, and an output whose request is 0 is left untouched. ## [v3.0.0-alpha.1] - 2026-09-03

The first pre-release of the 3.x line: the configuration layer of the versioned C ABI (`anira/abi/*.h`, ABI 0.1) with its JSON loaders, the C++20 builders of `anira/anira.hpp`, and a transitional bridge to the unchanged 2.x runtime. Nothing in it is a binary promise before v3.0.0: while the ABI major is 0 a library accepts only the exact ABI version its headers were generated with, and every pre-release may still change any of it. The soname stays 3 until the 3.x handler lands and flips it to the ABI major. The npm package is still the 2.x TypeScript API, published under the `next` tag.

## [v2.3.0] - 2026-09-02

anira v2.3.0 is the last release of the 2.x line. Development continues on the v3 branch (the versioned C ABI, `docs/anira-v3-architecture.md`); 2.x receives fixes only.

### Added

- One-sided streaming (#98, #99, #110): generators are driven by output demand, analysers read through `PrePostProcessor::get_output()`, and the `HostConfig` reference stream may be an input or an output (`m_tensor_is_input`, `HostConfig::k_first_streamable`). Mirrored in the WebAssembly/TS wrapper.
- ExecuTorch backend (`ANIRA_WITH_EXECUTORCH`, static-only): `.pte` programs, named entry points (`model_function`), prebuilt libraries for desktop, Android and iOS, a `minimal-executorch` example.
- Receptive-field (sliding-window) models in the default `PrePostProcessor`: an input tensor larger than its `preprocess_input_size` is filled with ring-buffer history plus the fresh hop.
- `Context` is immortal and owns the inference thread pool exactly while sessions exist (#104); `Context::shutdown()` for hosts that unload live, `release_core_if_idle()`/`has_core()` reclaim the core.
- `LatencyCalculator` (#66) replaces `SessionElement`'s latency arithmetic: closed forms instead of the LCM loop, `is_feasible()`, correct struct and ring sizing for fractional and smaller host blocks. Derivation in `docs/sphinx/latency.rst`.
- Symbol policy from the shared tanh-tooling CMake modules (`cmake/tanh/`): hidden visibility everywhere, `libanira` exports namespace `anira` only, plugins leak no backend runtime symbol; the `anira_exports` CTest enforces it.
- CI on the shared `tanh-lab/ci-actions` workflows: every backend and both linkages in the PR tier, install, sanitizer (ASan+UBSan, TSan, RTSan) and coverage legs, a preset for every leg in `CMakePresets.json`, and the npm publish gated behind the same tests as every other release artifact.

### Changed

- **Breaking:** the latency calculation moves out of `SessionElement` into `LatencyCalculator`; `SessionElement` loses its `calculate_*`, `max_num_inferences` and gcd/lcm helpers. Reported latencies are unchanged for whole-sample host blocks; slot counts follow `2·S`.
- **Breaking:** backend linkage follows `BUILD_SHARED_LIBS` and `ANIRA_<ENGINE>_LINKAGE` is gone: LibTorch (shared-only) is disabled in static builds, ExecuTorch (static-only) in shared builds.
- **Breaking:** no public header includes an engine header, and the engines are explicit imported targets that anira links `PRIVATE` (`anira::onnxruntime`, `anira::tflite`, `anira::litert`, `anira::libtorch`, `anira::executorch`). Migration: link `anira::<engine>` wherever your own code includes an engine header.
- **Breaking** (Windows install layout): DLLs install to `bin/`, import libraries and archives to `lib/`.
- **Breaking:** logging goes through tanh-lib's `thl::Logger` with a real-time queue (#56): `ANIRA_LOG_*`/`ANIRA_LOG_RT_*` replace the `LOG_*` stream macros, `ContextConfig::m_log_level` -> `ContextConfig::m_log` (`anira::LogConfig`), and the host owns the sinks.
- **Breaking:** `InferenceHandler::reset()` is wait-free and safe on the audio thread. Migration: call `prepare()` where a drain was relied upon.
- **Breaking** (containers): `anira::Buffer<T>`, `anira::RingBuffer` and `anira::MemoryBlock<T>` are aliases over tanh-lib's `thl::core` containers; `RingBuffer` no longer derives from `Buffer<float>`, and every real-time ring-buffer access uses the block API (#111).
- `Context::get_instance()` takes no arguments and returns a `Context&`; the `ContextConfig` travels with `Context::create_session()` (old two-step API deprecated for one minor release). `anira::HighPriorityThread` is deprecated for one release.
- The active backend defaults to the first model backend that is available instead of the silent `CUSTOM` bypass; `HostConfig`'s default reference tensor is the first streamable tensor.
- The export header is `anira/system/Exports.h`; `ANIRA_BUILDING`/`ANIRA_STATIC` replace `ANIRA_EXPORTS`/`ANIRA_STATIC_DEFINE` (old spellings honoured).
- ExecuTorch is consumed as one merged `libexecutorch.a` per platform, and the CMake >= 3.24 desktop floor is gone. The test suite builds as per-component binaries (`test_utils`, `test_scheduler`, `test_backends`, `test_handler`).
- Pins: tanh-lib `751b2b1`, anira-project/backends v2.4.0 (ExecuTorch 1.3.1, pre-isolated static desktop LiteRT).

### Removed

- `Context::release_instance()` and `Context::release_thread_pool()` (`Context::shutdown()` is the explicit teardown), the never-released `reset_non_blocking()` variants, the unreachable `ContextConfig::operator==`/`!=`, and the dead interpolation branch of `anira::calculate_percentile`.

### Fixed

- Backend runtime symbols are no longer exported from binaries embedding anira, which crashed hosts that ship their own runtime (Ableton Live 12 bundles ONNX Runtime).
- One-sided streaming: `SessionElement::prepare()` no longer hangs for generators or crashes for analysers, push-only pipelines no longer stall after `m_num_structs` chunks (#99), latency vectors are index-aligned with the outputs (#98).
- Session lifecycle: `Context::create_session()` no longer leaks the session count when a processor constructor or `prepare()` throws (#106); `create_session()`/`release_session()`/`prepare_session()` are thread-safe across sessions; a data race in `Context::release_session()` (found by the TSan leg).
- `LatencyCalculator::least_common_multiple` no longer overflows `int`, the `allow_smaller_buffers` sweep no longer stalls for large blocks, and the send ring of a fractional host block reserves `P - 1` samples.
- `JsonConfigLoader` drops malformed `tensor_shape` entries instead of letting `nlohmann::type_error` escape; `LibtorchProcessor` throws `std::runtime_error` on an unloadable model like the other backends; `BackendBase::process` no longer reads past the output vector.
- `USE_ANIRA_WEB` is defined in Emscripten builds only; installing on `lib64` hosts works with LibTorch and ExecuTorch; `anira::HighPriorityThread` links again in a Windows consumer of a shared anira; the JUCE example links under clang on Linux.
- Tests and CI: the macOS test-discovery race with CMake 4.4.0 (`DISCOVERY_MODE PRE_TEST`), the intermittently failing one-sided blocking-deadline tests, downloads retried after transient failures, and compile caching that works for the first time (`ACTIONS_CACHE_SERVICE_V2`).

## [v2.2.1] - 2026-07-04

### Added

- Batched overlapping-window extraction: a `pop_samples_from_buffer(...)` overload that extracts `num_batches` windows in one native call (also exposed to WebAssembly/TS), avoiding per-batch JS↔Wasm boundary crossings for batched/windowed models (e.g. HybridNN/GuitarLSTM).
- `PrePostProcessor::before_inference()` / `after_inference()` hooks, run on the inference thread right before/after the backend runs, letting stateful models (e.g. recurrent hidden-state feedback) splice state between consecutive inferences when combined with `session_exclusive_processor = true`. Wired up end-to-end in Anira Web (`registerPrePostProcessor`/`beforeInference()`/`afterInference()` on the TS side).
- Configurable inference-thread wait strategy: `anira::WaitStrategy { SpinBackoff, Blocking }` on `ContextConfig`. `Blocking` lets idle inference threads sleep on a semaphore instead of spin-polling, eliminating idle CPU usage at effectively no throughput cost; coerced to `SpinBackoff` with a warning on WebAssembly.
- Real-time factor and underrun reporting in the benchmark fixture (per-iteration RTF/`[underrun]` marker, plus an optional summary line with `rtf_mean`/`rtf_max`/underrun count).
- The `advanced` and `cnn-size` benchmarks now also cover the `CUSTOM` (no-inference) backend, and the benchmark CI workflow builds with tests enabled and runs the benchmark gtest suites.
- Configurable log level: `anira::LogLevel { Debug, Info, Warning, Error }` on `ContextConfig`, gating anira's own logging and forwarded to the ONNX Runtime, LiteRT and LibTorch backends (TFLite excepted — no runtime logging control in that prebuilt library). Defaults to `Info` in debug builds, `Error` in release builds.
- Anira version mismatch reporting in `Context::get_instance`: a differing major version between sessions is now reported as an error, a differing minor/patch as a warning.
- `Context::get_num_inference_threads()` / `InferenceHandler::get_num_inference_threads()`: number of inference threads currently active process-wide (also exported to WASM).

### Changed

- `ContextConfig`'s default `num_threads` is now platform-dependent: half the available CPU cores (as before) on native builds, `0` on WebAssembly, since inference threads there are always supplied externally via `AniraWeb.spinUpInferenceWorker()`.

### Fixed

- Stateful in-order dispatch (`session_exclusive_processor = true`) no longer allocates on the audio thread — `SessionElement`'s pending-dispatch queue is now pre-sized and fed through an explicit producer token.
- Web: the audio worklet now polyfills `performance.now()` before the WASM module loads, fixing a `ReferenceError` (observed in Firefox) whenever a blocking-ratio deadline was read from the audio thread.
- The advanced benchmark no longer instantiates ONNX Runtime for the stateful RNN model, whose fixed 2048-sample ONNX export failed warm-up at other buffer sizes.
- Use-after-free when a pooled backend processor outlived the session that created it — `InferenceConfig` is now owned per-processor instead of aliasing the originating session's copy.
- Windows build failure in `Context::get_instance()` caused by `<windows.h>`'s `min`/`max` macros mangling an unrelated `std::min(...)` call; fixed by defining `NOMINMAX`/`WIN32_LEAN_AND_MEAN` before the include.
- Hardened `SessionElement::m_is_non_real_time` to `std::atomic<bool>` and unified the two `new_data_request()` wait paths onto one `wait_for_completion()` helper — previously a default-`blocking_ratio` session in non-real-time mode could free an in-flight buffer while the inference thread was still writing to it. Non-real-time mode also now works on WebAssembly once an inference worker is running.

## [v2.2.0] - 2026-06-23

### Added

- **Android support** (`arm64-v8a` + `x86_64`): the library, the prebuilt backends, and the full gtest suite running on a KVM-accelerated emulator, all wired into CI (`build_test_mobile.yml`). The glibc-only `pthread_*inheritsched` / `pthread_setattr_default_np` calls are gated behind `!__ANDROID__` (bionic lacks them) while keeping the portable `SCHED_FIFO` path.
- **iOS support** (device + simulator): the library and prebuilt backends shipped as an xcframework, with the full gtest suite running on the simulator in CI. Per-SDK xcframework slice selection; TFLite is consumed as a `TensorFlowLiteC.framework` via a generated shim so anira's `<tensorflow/lite/...>` includes resolve untouched.
- **LiteRT inference backend** (`anira::InferenceBackend::LITERT`): runs `.tflite` models through Google's native `LiteRt*` C API / CompiledModel runtime. Enabled by default (`ANIRA_WITH_LITERT=ON`) as the modern TensorFlow-Lite-family backend; wired into the examples and benchmarks.
- Data-driven backend downloads: prebuilt backends are fetched at configure time from the [`anira-project/backends`](https://github.com/anira-project/backends) release, pinned by `ANIRA_BACKENDS_VERSION`.
- Live backend integrity check: when GitHub is reachable, anira fetches each asset's published SHA256 and re-downloads any backend whose archive changed upstream or downloaded incompletely, instead of a committed hash lock. `ANIRA_BACKENDS_SKIP_REMOTE_CHECK=ON` skips the remote query for offline/reproducible builds.
- Bring-your-own-backend knobs: `ANIRA_<ENGINE>_ROOTDIR` (prebuilt tree), `ANIRA_<ENGINE>_URL` + `ANIRA_<ENGINE>_SHA256` (custom source), and per-engine `ANIRA_<ENGINE>_LINKAGE=shared|static`.
- clang-tidy conformance across the library, tests and benchmark sources, enforced in CI via the `tanh-lab/ci-actions/clang-tidy-check` action (`clang_tidy.yml`)
- `InstallConsumer` smoke test that builds against the installed package to catch packaging regressions.
- Release pipeline now publishes every tested arch×linkage artifact with backend-consistent naming: Android (static), iOS (xcframework), and Linux/macOS/Windows × `shared`/`static`, including macOS `universal`.

### Changed

- **Breaking:** the `InferenceConfig::Defaults` compile-time constants were renamed from the `m_` prefix to the `k_` prefix to match the constant-naming convention (`m_warm_up` → `k_warm_up`, `m_session_exclusive_processor` → `k_session_exclusive_processor`, `m_blocking_ratio` → `k_blocking_ratio`). The mutable `Defaults::m_num_parallel_processors` is unchanged.
- LiteRT is now the default TensorFlow-Lite-family backend. The legacy TensorFlow Lite backend (the older `TfLite*` C API, `ANIRA_WITH_TFLITE`) is the **same runtime** exposed through a different C API, so the two are now **mutually exclusive** — enable the legacy path with `-DANIRA_WITH_LITERT=OFF -DANIRA_WITH_TFLITE=ON`.
- `nlohmann_json` is now consumed as a release download instead of a git submodule.
- CMake options and their validation were consolidated inline into `CMakeLists.txt` (`AniraOptions.cmake` and the redundant linkage knob were dropped).
- `anira::calculate_min` / `anira::calculate_max` are now `inline` free functions instead of `const auto` lambdas (source-compatible: existing call sites and uses as a callable are unaffected)
- The internal logging helper `isLoggingEnabled()` was renamed to `is_logging_enabled()`
- Migrated the shared clang configs (`.clang-format`/`.clang-tidy`/`.clangd`) from the `tanh-lib` submodule symlinks to [`tanh-tooling`](https://github.com/tanh-lab/tanh-tooling) (pinned `v0.1.4`): committed as real files, kept in sync by the `clang_check.yml` drift check, and the now-unused `tanh-lib` submodule was removed (configs are byte-identical, so lint/format results are unchanged)
- Adopted the default Claude Code config: `.claude/settings.json` now enables the `tanh-tools` plugin from the tanh-tooling marketplace (its format/lint/type-check hooks supersede the previous bespoke `.claude/hooks`)
- CI now covers Windows-`arm64`, Linux-`aarch64` and macOS-`universal` legs (shared + static) in addition to the mobile workflow.

### Fixed

- Potential use-after-free in `Buffer::malloc_channels()` when channel-pointer allocation fails
- Installed `nlohmann_json` config so `find_package(anira)` works against the installed package
- Disabled backends now compile to empty translation units (guarded `.cpp` bodies), and `minimal-onnxruntime` is self-sufficient in static builds
- Value-initialize the `const InferenceConfig` in the install consumer
- clang-tidy violations and a CLAP static MSVC runtime mismatch; preserve the anira-before-`JuceHeader` include order on MSVC; qualified `mem*` calls with `std::` and added `<cstring>`
- Windows shared-DLL copy, the examples target list, and arm64 LibTorch in CI
