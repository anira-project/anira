- **ABI (unstable):** `anira/abi/tensor.h`, the runtime tensor of section 1 (ABI 0.2; 150 promised names). Three Tier-1 records, frozen with no `struct_size` and no version field, identical on wasm32, LP64 and LLP64: `anira_tensor` (216 bytes: `domain`, `dtype`, `ndim`, `flags`, `shape[8]`, `strides[8]` in elements with all-zero = packed row-major, `byte_offset`, `handle`, `manager_ctx`, `release`, `acquire`), the union `anira_memory_handle` (24 bytes, the thirteen arms `host`, `cuda`, `gl`, `vk`, `opaque`, `mtl`, `iosurface`, `wgpu`, `dmabuf`, `ahb`, `d3d12`, `planes`, `raw[3]`, every vendor handle at its wire width) and `anira_sync_token` (24 bytes: `kind`, `flags`, the payload union `u`), with the release callback `anira_tensor_release_proc`, a function type that sits in an `ANIRA_PTR` slot (`[thread-safe, !audio-thread]`, not real-time: it runs on an inference thread or on the caller of poll / wait / prepare / destroy, never on the driver thread). The factories `anira_tensor_init_host` / `pinned` / `cuda` / `gl_buffer` / `vulkan` / `opaque_fd` / `wgpu_buffer` / `dmabuf` zero the caller's record and then fill it, `[thread-safe]` `[callback-safe]` `ANIRA_NONBLOCKING`, and return nothing: a dtype of 0, a rank above `ANIRA_MAX_RANK`, a NULL shape with a rank above 0 or a negative extent leave the record all-zero, which no filled record is; every argument is read before the record is zeroed, so `shape` and a token may point into the record being filled (`anira_tensor_init_host(&t, p, t.dtype, t.ndim, t.shape)` re-points a tensor), and the previous content is overwritten, never released; a NULL fence, a timeline semaphore of 0 and a negative `sync_fd` mean `ANIRA_SYNC_NONE` (anira never fabricates a fence), a token passed by pointer is copied and that copy is the hand-off, a `sync_fd` of 0 or more is owned by the record's `acquire` from there on, and a refused call takes neither the token nor the fd. Planar host memory is part of the tensor, contained: `ANIRA_TENSOR_PLANAR = 8` is appended to `anira_tensor_flags`, the `planes` arm holds `ptrs`, `count` and `reserved`, `anira_tensor_init_host_planar(tensor, planes, count, dtype, ndim, shape)` fills it from one pointer per plane of axis 0 (the channel pointers of an audio host; `planes` is `const void*`, so a `float**` and a `const float* const*` convert without a cast in C and in C++; `count` must equal `shape[0]` and the rank be 1 or more, else the record stays all-zero) and `anira_tensor_plane(tensor, plane, dtype)` reads one plane with `byte_offset` applied. It is a boundary representation of the two host domains: only an entry whose own documentation says so accepts a planar tensor, every other consumer and every other domain refuses the flag with `ANIRA_ERROR_NOT_SUPPORTED`, and `anira_tensor_data` / `anira_tensor_data_f32` return NULL for one. `anira_tensor_init_dlpack(tensor, dl_managed_tensor_versioned, err)` (`[main-thread]`; `anira_error*` last, which the design document's sketch lacks) bridges a DLPack 1.x `DLManagedTensorVersioned` handed over as `void*`: `kDLCPU` is `ANIRA_DOMAIN_HOST`, `kDLCUDAHost` `ANIRA_DOMAIN_HOST_PINNED`, every other device and every dtype code above 6 `ANIRA_ERROR_NOT_SUPPORTED`, as is a major other than 1 (nothing past the version is read); shape and strides are copied (NULL strides = packed row-major; strides that are present and all zero over more than one element, a fully broadcast view, are `ANIRA_ERROR_NOT_SUPPORTED`, because all-zero is this record's spelling of packed), `DLPACK_FLAG_BITMASK_READ_ONLY` sets `ANIRA_TENSOR_READ_ONLY`, `release` is a trampoline that disarms the record and calls the producer's deleter exactly once (a NULL deleter is a borrowed tensor); a refused call leaves `*tensor` untouched and never calls the deleter. The accessors `anira_tensor_data_f32` (host and pinned float32 only, `byte_offset` honoured, NULL otherwise), `anira_tensor_data(tensor, dtype)` (NULL unless `dtype` is the tensor's own; never converts), `anira_tensor_num_elements` (1 at rank 0, 0 with a zero extent and for the dtype-0 record of a refused factory) and `anira_tensor_extent` (0 at and beyond `ndim`), and `anira_sizeof(anira_struct_id)` for allocators that cannot see the header: ten records answer, `ANIRA_STRUCT_STAGE_CTX` and every unknown id return 0. `anira_sync_token_reset` / `anira_sync_token_dup` (`[thread-safe, !audio-thread]`: closing and duplicating are system calls) end and duplicate the descriptor of the two owning fd kinds, a plain zero and a plain copy for every other kind: an fd of 0 or more on POSIX (`close`, and a close-on-exec duplicate), an NT handle above 0 on Windows (`CloseHandle`, `DuplicateHandle`), nothing on WebAssembly, where reset closes nothing and a duplicate of an owning kind is `ANIRA_ERROR_NOT_SUPPORTED`. Tests: `test_Tensor` (`AbiTensor`, `AbiTensorSync`, `AbiTensorDlpack`: zero-then-fill of all thirteen factories byte for byte, the planar tensor, the NULL rules, fd ownership over a pipe, the bridge over the tests' own spelling of dlpack.h in `test/abi/dlpack_producer.h`) in `test_abi`; gate 3 pins 216/24/24 and every offset through the union arms, gate 4 covers the header from C11, C++17 and alone.
- **ABI (unstable):** the Hard entries over host tensors, under the bare names of `anira/abi/handler.h`, which includes `anira/abi/tensor.h` now (ABI 0.2; 160 promised names): `anira_handler_process(handler, in, out, tensor_index, delivered)`, `anira_handler_process_multi(handler, inputs, num_inputs, outputs, num_outputs, delivered)`, `anira_handler_push_data(handler, in, tensor_index)`, `anira_handler_push_data_multi(handler, inputs, num_inputs)`, `anira_handler_pop_data(handler, out, tensor_index, delivered)`, `anira_handler_pop_data_multi(handler, outputs, num_outputs, delivered)` (`[driver-thread]`, `ANIRA_NONBLOCKING`) and the four `_wait` twins `anira_handler_process_wait`, `process_multi_wait`, `pop_data_wait`, `pop_data_multi_wait` (`[any-thread, blocking]`; `timeout_ms` follows the blocks in the single forms and is the last parameter of the multi forms). A host block is one `const anira_tensor*` per slot, an output's included: a descriptor is never written, the memory it names is, so a host builds its tensors once and reuses them. The logical shape is `[channels, samples]` (`[1, values]` for a Static slot), the sample count is `shape[1]` (no `num_in` / `num_out`), and the memory is planar (`ANIRA_TENSOR_PLANAR`: these are the entries that accept the flag), one block read by `strides` (contiguous `{samples, 1}`, interleaved `{1, channels}`) or one packed block (all-zero strides), for any channel count; the two sides of a call may be described differently, and one tensor handed over as input and output is in place (there is no `_inplace` name). The tensor's dtype must be the slot's (the ring dtype of a Streamed slot): nothing converts, and another dtype is `ANIRA_ERROR_CONFIG`. A malformed descriptor is `ANIRA_ERROR_INVALID_ARGUMENT` (a rank other than 2, which includes the zeroed record a refused factory leaves, a domain other than `ANIRA_DOMAIN_HOST` and `ANIRA_DOMAIN_HOST_PINNED`, `ANIRA_TENSOR_READ_ONLY` on an output, `shape[0]` other than the slot's channel count, a negative `shape[1]`, and with samples: NULL memory, a plane count other than `shape[0]`, a NULL plane, a negative stride, a stride of 0 on an axis longer than 1 unless every stride is 0, a channel that does not start on a multiple of the element size), a flag bit this library does not know is `ANIRA_ERROR_NOT_SUPPORTED`, and the check order is fixed: rank, domain, flags, shape, dtype, memory and strides, the input before the output. Every tensor of a call is validated before anything is pushed, so a refusal writes no ring. An empty tensor (`shape[1] == 0`; its memory arm is not read, NULL is legal) leaves a slot out; the multi forms take exactly one tensor per slot, Static slots included, and refuse another `num_inputs` / `num_outputs` with `ANIRA_ERROR_INVALID_ARGUMENT`. `delivered`, single and multi, is a nullable pure out parameter written on every return: zeroed first, then `shape[1]` of each output on `ANIRA_OK` (clamped to the tensor's size for a Static output), 0 on `ANIRA_MISSED` and on a failure, and on the `ANIRA_ERROR_INVALID_STATE` of a `_wait` twin what the nonblocking stem delivered. It is never read: the request is `shape[1]` of each output tensor, so a miss leaves nothing to refill. `release`, `manager_ctx` and `acquire` are not read: the memory is borrowed until the call returns. There is no float-only family of entries: a host that holds channel pointers builds one planar tensor over its pointer array with `anira_tensor_init_host_planar`, once, and stores `shape[1]` before each call. `anira_handler_rt_error` latches one more kind, `ANIRA_ERROR_NOT_SUPPORTED` (`anira::RtKind::NotSupported`). Tests: `test_HandlerTensor` (`AbiHandlerTensor`) in `test_abi`: every description against absolute expectations (each channel its own ramp, late by the reported latency) for 1, 2, 3 and 6 channels, crossed descriptions, in place, the multi forms with a Static slot and the clamped count, the single forms beside unused slots, the three miss policies, every refusal with its status, its latched record and the check order, and every descriptor compared byte for byte around its call; the named comparisons that stand in for one oracle (the entries and the 2.x handler share the copy path, and a pass-through cancels a symmetric stride bug): a white-box look at the send ring after `anira_handler_push_data` under every description, a planar against an interleaved description over one script with missed blocks under the three policies, bit for bit, and an interleaved stereo block with the Static gain as `[1, 1]` through `anira_handler_process_multi` against the 2.x `anira::InferenceHandler` in one binary on the bundled stereo gain model (`stereo_gain_with_custom()`), on every plan this build has an engine for and on the custom row (through a real engine that covers two channels; three and six channels run through the engine-free pass-through); `test_Prepare` runs its miss sequence over planar and over packed tensors, under `ANIRA_MISS_CALLBACK` too, `test_HandlerWait` drives the four tensor twins (a deadline is `ANIRA_MISSED`, `ANIRA_WAIT_FOREVER` delivers); `test_rt_contract.c` calls the six nonblocking entries from an `ANIRA_NONBLOCKING` function, `header_c.c` and `header_cxx17.cpp` call one.
- **ABI (unstable):** the fourth miss policy, `ANIRA_MISS_CALLBACK = 3` (appended to `anira_miss_policy`; `"on_miss": "callback"` in a contract file), with the backup function `anira_miss_fn` and its setter `anira_contract_hard_set_miss_fn(contract, fn, user_data)` in `anira/abi/config.h`, which includes `anira/abi/tensor.h` now (`[main-thread]`; `ANIRA_ERROR_WRONG_CONTRACT` on an Async contract, `ANIRA_ERROR_INVALID_ARGUMENT` for a NULL contract, a NULL `fn` clears the pair; 161 promised names). `typedef anira_status (ANIRA_CALL* anira_miss_fn)(anira_handler* handler, const anira_tensor* inputs, uint32_t num_inputs, const anira_tensor* outputs, uint32_t num_outputs, void* user_data) ANIRA_NONBLOCKING;` is the first `ANIRA_NONBLOCKING` function-pointer typedef of the ABI (`[driver-thread]`; a `_wait` twin calls it on the waiting thread). It fills a whole missed block, every slot at once and whatever the slots' dtypes: one call per missed block on the thread that called the entry, with the very arrays the copy path was handed, so nothing is built on a miss: the caller's own tensors under a tensor entry (a single-tensor form on a side with several slots passes the handler's array: the caller's descriptor in its slot, empty tensors beside it, which name no memory, since a staged slot is the empty tensor of prepare again when its call returns and no pointer of an earlier call stays in it), and empty inputs in a pop. The input block of a process form is already pushed and still intact in host memory, in place too. `ANIRA_OK` means the outputs are filled; any other status makes anira zero-fill every requested output. Either way the block counts as missed: the entry returns `ANIRA_MISSED` with a delivered count of 0 and the stream stays time-aligned, and a `_wait` twin without an inference thread still returns `ANIRA_ERROR_INVALID_STATE`, after the function ran. The function must not call a Hard entry, `anira_handler_reset` or `anira_handler_prepare` of the same handler, and under clang a function converted to `anira_miss_fn` must itself be declared `ANIRA_NONBLOCKING`. The two setters work in either order; the policy without a function is `ANIRA_ERROR_CONFIG` at `anira_handler_prepare`, naming `on_miss` (that is where a contract parsed from a file, which cannot carry a function, is caught: set the pair on the parsed contract first); the pair is copied with the contract and must outlive the prepared handler. Prepare also refuses `ANIRA_MISS_BYPASS` when a streamed output's ring dtype differs from the anchored input's (it cannot fire while every ring is float32). Scheduler: `InferenceManager::set_miss_hook(hook, ctx)` and a `case ANIRA_MISS_CALLBACK` in the starvation path of `process_output`, called once before the per-output fill; the accounting of a missed block is the same under every policy. A stage is a descriptor, `anira_stage_desc` (Tier 2, 96 bytes on LP64 and 60 on ILP32, no implicit padding; `ANIRA_STAGE_DESC_INIT`): `struct_size`, `abi_version`, `user_data`, a `name` (copied; NULL or empty reads `stage#<index>`), the two domains (`ANIRA_DOMAIN_HOST` in this pre-release, anything else is `ANIRA_ERROR_NOT_SUPPORTED`), `consumed_kinds` (`"<host>:<kind>"` strings that join the consumed-or-fail walk and appear as `anira_plan_ext` rows whose consumer is the stage's name), the four phase slots `pre_process`, `post_process`, `before_inference`, `after_inference` (`anira_stage_fn`), `prepare` (`anira_stage_prepare_fn`, called at the end of every `anira_handler_prepare` with the handler and the plan report, a status other than `ANIRA_OK` failing the prepare by name) and `release` (`anira_stage_release_fn`). `anira_pipeline_add_stage` copies `min(struct_size, sizeof)` bytes into a refcounted carrier that the pipeline and every handler created from it share, so `release` fires exactly once, with the last of them. The rings stay inside anira: the new handle `anira_ring` and its ten accessors `anira_ring_dtype`, `anira_ring_num_channels`, `anira_ring_available`, `anira_ring_available_past`, `anira_ring_pop_block`, `anira_ring_peek_past_block`, `anira_ring_push_block`, `anira_ring_push_fill`, `anira_ring_discard` and `anira_ring_pop_windows` (`[driver-thread] [callback-safe] ANIRA_NONBLOCKING`); a data accessor states the dtype it believes the ring holds and, when it is another one, returns 0, moves nothing and records `ANIRA_ERROR_CONFIG` in `anira_handler_rt_error` with one latched record naming the stage (a channel out of range or NULL memory: `ANIRA_ERROR_INVALID_ARGUMENT`; a NULL ring: 0). The two default bodies `anira_stage_default_pre_process` (the receptive-field fill of the 2.x default processor, channel `c` of a tensor at `c` times its elements per channel) and `anira_stage_default_post_process` (the plain push) are callable from a stage ("call super") and return `ANIRA_ERROR_CONFIG` for a slot whose ring dtype is not its tensor's, leaving it untouched. The chain: the filled slots of a phase run in chain order in all four phases; the default body of a phase runs once per chunk and only when no stage fills that slot; after pre_process every Streamed input ring must have given up exactly its hop per channel and after post_process every Streamed output ring must have gained it, a shortfall being repaired (discarded, or topped up with zeros) and either deviation recorded as `ANIRA_ERROR_CONFIG` with one latched record naming the stages, the tensor and both counts; a phase callback that returns anything but `ANIRA_OK` ends its phase, puts its status into `anira_handler_rt_error` with one latched record naming the stage and makes the chunk deliver zeros at its stream position (a failed pre_process is not submitted, a failed hook skips the engine call or zeroes the outputs, a failed post_process is topped up). `anira_stage_fn` and the two defaults carry the new dual thread tag `[driver-thread | inference-thread]`: pre_process and post_process run on the thread that drives the Hard entry, the two hooks on an inference thread. `test_rt_contract.c` gains a nonblocking phase callback over every accessor and both defaults; `header_c.c` and `header_cxx17.cpp` pin the descriptor's initializer, the typedefs in its slots and the 64 bytes.

- tanh-lib v0.4.0 pinned for the strided ring calls (tanh-lab/tanh-lib#50: `thl::core::RingBuffer<T>::push_block`, `pop_block` and `peek_past_block` take a `stride`, counted in elements, so one channel of an interleaved block moves between the host's memory and a ring in one copy, without a de-interleaved block in between). `anira_ring` (`anira/utils/RingBuffer.h`) forwards it: the dtype-checked `push_block`, `pop_block` and `peek_past_block` gain `size_t stride = 1` as their last parameter (1 or more; 1 is the packed run and the unit-stride path of the storage; a disagreeing dtype still returns 0 with nothing written; a push larger than the capacity keeps its tail and a pop beyond the available count value-initialises the strided tail and nothing between), and `element_size()` reports `sizeof(T)` of the instantiation behind the ring's dtype. The float face and `pop_windows` are unchanged, and nothing in the scheduler uses the stride yet. tanh-tooling stays v0.2.8 on both sides.
- **One host<->ring copy path, over `anira_tensor`.** `InferenceManager`'s `process_input`, `process_output` and the three miss policies (`hold_output`, `bypass_output`, `clear_output`) are written once over `const anira_tensor*`, one tensor per slot in slot order, and the float face of the library, `anira::InferenceHandler`, runs on it: it keeps its signatures, its in/out count protocol and its return values and presents the caller's channel pointers as planar float32 tensors that prepare builds once (a call stores `shape[1]` and one pointer per channel; nothing is allocated on the driver thread). Every block it delivered before it delivers bit for bit: the float core was recorded first (`test_scheduler` suite `CopyPathOracle`, `test_abi` suite `AbiHandlerCopyOracle`: every float a call writes and every float it leaves alone, under the three miss policies) and the rewritten core reproduces the recording. New on `InferenceManager`, as the C++ face the tensor entries call: `process_nowait(inputs, outputs)`, `process_wait(inputs, outputs, budget, outcome)`, `push_data(inputs)`, `pop_data(outputs)`, `pop_data_wait(outputs, budget, outcome)` and `contract_wait_budget(inputs, outputs)` over `const anira_tensor*` arrays, returning the manager's own array of delivered counts, and the two 2.x behaviours in the same form: `process(inputs, outputs)`, the dispatcher on `blocking_ratio`, and `pop_data(outputs, wait_until)`, the deadline pop. A slot's tensor is a host block of the logical shape `[channels, samples]` (`[1, values]` for a non-streamable slot) in any of three descriptions, for any channel count: planar (`ANIRA_TENSOR_PLANAR`, `byte_offset` and `strides[1]` inside each plane), one block read by `strides` (interleaved is `{1, channels}`, contiguous `{samples, 1}`), or one block with all-zero strides (packed). Each channel moves between host memory and the ring in one strided ring call, with no intermediate copy; a unit stride is the ring's plain block copy, as before. The request is `shape[1]`; a slot whose `shape[1]` is 0 is not touched and its memory is not read; a descriptor is never written; in place is the same tensor on both sides. The copy is dtype-generic: the element type is the tensor's, which must be the slot's ring dtype (float32 for a non-streamable slot), nothing converts, and `HOLD_LAST` holds bytes of the ring's element type. The stems trust their descriptors (the caller validates them; `src/scheduler/TensorRun.h` carries that check, `check_host_tensor`, beside the run helper) and check the dtype only: a mismatched input is not pushed, a mismatched output is zero-filled and reports 0 samples, logged once through the real-time queue under the new site `RtSite::TensorDtypeMismatch`. That also ends a silent failure of a float32 call on a session prepared with a non-float32 `RingDtypes` entry, which pushed and popped nothing and still reported a delivered block over memory it had not written. On a `BYPASS` miss, input and output memory that overlap under two different descriptions are undefined; the identical run (in place) is left where it is.
- **Breaking (the manager's C++ face):** `anira::InferenceManager` takes host tensors only. Its seven `float***` overloads are gone from the installed header `anira/scheduler/InferenceManager.h`: `process`, `process_nowait`, `process_wait`, `push_data`, `pop_data`, the deadline form of `pop_data` and `pop_data_wait` over `const float* const* const*` / `float* const* const*` beside `size_t*` count arrays, and with them the count-array form of `contract_wait_budget` (the tensor form measures the block by `shape[1]` of the anchored tensor). The float adapter they shared with the rest of the library moved out of the manager into one private helper, `anira::PlanarFloatAdapter` (`src/scheduler/PlanarFloatAdapter.h`, not installed), which `anira::InferenceHandler` owns, so nothing changes for its users: every `process`, `push_data` and `pop_data` overload keeps its signature, its count protocol and every float it delivers (the recorded copy-path suites `CopyPathOracle` and `AbiHandlerCopyOracle` pass with their transcripts untouched). This change touches no C entry and no registry line; the C ABI change of the same cycle is under Removed. Migration, for code that drives an `InferenceManager` directly: present one `anira_tensor` per slot to the tensor form of the same name. For channel pointers that is `anira_tensor_init_host_planar(&t, channels, num_channels, ANIRA_DTYPE_F32, 2, shape)` with `shape = {num_channels, num_samples}` (`{1, num_values}` for a non-streamable slot), a slot the call leaves out is an empty tensor (`shape[1] == 0`, memory may be NULL), in place is the same tensor on both sides, and the returned `const size_t*` is the manager's own array of delivered counts (0 for every slot of a missed block), so the caller's request array is no longer overwritten.
- A Static or a Buffer tensor spec may carry a Channel axis of any extent: `anira_handler_create`, `anira_handler_prepare` and the 2.x bridge no longer refuse such a spec with `ANIRA_ERROR_CONFIG` ("a Static tensor's Channel axis must have extent 1"). The Channel tag maps onto ring channels on a Streamed tensor only; a non-Streamed tensor has the spec's shape, the tagged axis being one of its axes, and moves as the product of its extents (the 2.x config the translator builds carries it as one channel with the full dims in every shape). At most one Channel axis per spec stays the rule for every role.
- A ring dtype that differs from its tensor spec's dtype is no longer `ANIRA_ERROR_CONFIG` at `anira_handler_prepare` when a stage of the pipeline fills the phase that moves that ring (`pre_process` for an input ring, `post_process` for an output ring): the stage pops or pushes the ring's element type itself and converts, since nothing in anira does. Without such a stage the refusal stands, as it does for the 2.x bridge; the default stage bodies refuse such a slot at run time. The registry docs of `anira_contract_hard_set_ring_dtype` and `anira_handler_prepare`, `anira::ContractHandle::hard_ring_dtype` and `usage.rst` 1.3 say so.
- The session of a C-created handler runs one processor, the stage chain (`StageChainProcessor`, `src/capi/stage.cpp`), whether its pipeline has a stage or not: without one the chain runs the two default bodies, which are the streamed branches of the 2.x default `PrePostProcessor`, and both recorded copy-path oracles stay byte-identical. Static tensors still travel through the processor's float atomics. `anira_ring` (`anira/utils/RingBuffer.h`) gains `set_owner` / `hop` / `owner` (the hop of its slot and the owning session's `anira::RingOwner`: the latch a refused accessor records into and the stage running on the driving thread), set by `SessionElement::prepare`; `SessionElement::ThreadSafeStruct` gains `m_stage_status`, which `Core::pre_process` and `InferenceThread::do_inference` read after the processor's hooks (a 2.x processor never writes it); `anira::RtLatch` gains `record_any` and `RtKind::Other`, so that a stage's status without a kind bit of its own still reaches `rt_error`; `InferenceManager::session()` hands the chain the session it binds to.
- The 2.x `anira::InferenceHandler` routes the non-streamable tensors of its `float***` blocks itself. `anira::NonStreamableRouter` (`src/scheduler/NonStreamableRouter.h`, private to the library like `PlanarFloatAdapter`, which it stands beside) wraps every tensor stem of `InferenceManager`: it stores the carried non-streamable inputs in the session's `PrePostProcessor` (the count clamped to the tensor's size), hands the stem views of the two tensor arrays in which every non-streamable slot is left out, and reads the requested non-streamable outputs back afterwards (the clamped count on a delivered block; on a missed block `HOLD_LAST` writes `min(request, size)` values and every other policy zeroes the request as it came, the count 0). It is the copy core's non-streamed code moved as it was, over tensor arrays, so `InferenceHandler`, the `CopyPathOracle` rig and the `TensorStems` replays (which present the Static tensors under every memory description) go through it and both recorded oracles stay byte-identical; nothing changes for a 2.x caller. The core's own non-streamed branches are still in place and are no longer reached from the 2.x face. `InferenceManager::miss_policy()` reads back what `set_miss_policy()` stored.


### Fixed

- `InferenceManager::set_plan_backends` / `SessionElement::set_plan_backends` throw `std::logic_error` on a prepared session instead of replacing a table the driving and the inference threads read without synchronization (the before-prepare rule was documented, not enforced); `InferenceManager::prepare()` clears `last_block_missed()`, as its documentation says. Tests: `BackendSwitch.ThePlanTableIsReplacedBeforePrepareOnly`, `BackendSwitch.ABackendWithoutAPlanLeavesTheSelection` (the 2.x selection by backend on a table with no row for it).
- `AbiPrepare.ThePlanReportIsLoggedAtInfo` asserts its records under `ENABLE_LOGGING` only, like every other record assertion in `test_abi` (a build with `ANIRA_WITH_LOGGING=OFF` compiles the plan-report log out).
- Docs: `logging.rst` and the error and log strategy say what a real-time refusal returns now (the failure status, the count 0) and that a missed block is not a refusal; `ANIRA_TIMEOUT` and `ANIRA_MISSED` reference each other (a `_wait` entry's timeout is `ANIRA_MISSED`); `contributing.rst` names the clang-tidy changed-files rule and refers to each branch's ruleset instead of "ten contexts".
- **A backend switch while audio runs could run two engines for one chunk, or none.** `InferenceThread::inference()` loaded the session's backend atomic again in every engine block, and the blocks were independent: a `set_inference_backend` / `anira_handler_set_plan` that landed during an engine call ran a second engine on the same chunk when the new backend's block came later in the function (double cost, a missed budget, a Stateful model stepped twice), and one that landed between two blocks could skip every block, leaving the chunk's output tensors as its struct last held them. `inference()` now takes the backend as a parameter and dispatches through one `switch`: exactly one processor runs per call.
- **One chunk could be handled under three different backends.** `Core::pre_process`, the inference thread and `Core::post_process` each loaded the session's backend on their own, so a switch that landed while a chunk was queued or in flight told its `pre_process`, its `before_inference` / `after_inference` hooks, its engine and its `post_process` different backends (a 2.x pre/post processor that fills tensors per backend then fed one backend's layout to another). The chunk is now stamped with one load at submission (`SessionElement::ThreadSafeStruct::m_plan`, the dense plan index, written in `Core::pre_process`) and every later step resolves the stamp through the session's plan table: a switch applies from the next submitted chunk on, and a chunk that is queued or in flight finishes on the backend it started on. Documented on `InferenceHandler::set_inference_backend` and `InferenceManager::set_backend`, whose doc no longer claims a session reinitialization.
- **`anira_handler_set_plan` from several threads could leave `anira_handler_get_plan` naming one plan while another plan's engine ran.** The entry is `[thread-safe]` but stored the dense index and the session's backend separately; two interleaved calls could keep the index of one and the backend of the other until the next call. The selection is now one atomic, and it is the dense plan index, not the backend: `SessionElement::m_current_plan` beside a plan table (`m_plan_backends`, index -> backend) that the handler hands to the session before it prepares it (`InferenceManager::set_plan_backends`), with `InferenceManager::set_plan` / `get_plan` as the one store and the one load behind `anira_handler_set_plan` / `get_plan`. The chunk stamp above is that index (`ThreadSafeStruct::m_plan`). An engine value could not be the selection once two plans share an engine (two variants of a model, two providers); the index can. A 2.x session builds its own table (one row per configured model in `m_model_data` order, then every other backend of the build), and `set_inference_backend` / `InferenceManager::set_backend` select the first plan on the backend; a backend no plan runs on leaves the selection unchanged and is logged once (`RtSite::BackendWithoutPlan`), which a 2.x table never reaches. The docs of both C entries in `anira/abi/handler.h` say so.
- Tests: `BackendSwitch.AChunkInFlightFinishesOnTheBackendItWasSubmittedUnder` (a chunk held in `before_inference` while the switch lands; fails against the old reads), `BackendSwitch.EveryStepOfAChunkIsToldTheStampedBackend`, `BackendSwitch.TwoPlansOnOneBackendStayDistinct` (two plans on one backend read back as themselves and the chunk carries the index), `BackendSwitch.AnIndexOutOfRangeLeavesTheSelection`, `BackendSwitch.TheDefaultTableNamesEveryBackendOfTheBuild` and `AbiHandler.ConcurrentSetPlanLeavesOneSelection`; the in-flight test and the concurrent one need an engine in the build and skip without one.

### Removed

- **Breaking (pre-release ABI 0.x):** the twelve float32 Hard entries of `anira/abi/handler.h` are removed: `anira_handler_process_f32`, `anira_handler_process_f32_inplace`, `anira_handler_process_f32_multi`, `anira_handler_push_data_f32`, `anira_handler_push_data_f32_multi`, `anira_handler_pop_data_f32`, `anira_handler_pop_data_f32_multi` and the five `_wait` twins `anira_handler_process_f32_wait`, `anira_handler_process_f32_inplace_wait`, `anira_handler_process_f32_multi_wait`, `anira_handler_pop_data_f32_wait`, `anira_handler_pop_data_f32_multi_wait` (161 promised names, 167 wasm exports). They were added and removed within this unreleased cycle: `v3.0.0-alpha.1` does not carry them (it has no handler entry at all), so only builds from `v3` snapshots are affected, and the entries above describe the handler surface without them. Each one was the tensor entry of the same name over a planar float32 tensor, which is what its body built through `anira::PlanarFloatAdapter`; kept, they would have frozen twelve names at 3.0.0, a second count protocol (`num_out` of the multi forms was the request and the result at once, and a missed block once zeroed the request of a host that reused the array) and a float-only family on a surface that is dtype-generic. The entries under the bare names (`anira_handler_process`, `push_data`, `pop_data`, their `_multi` forms and the `_wait` twins) are the only Hard entries. `ANIRA_ABI_MAJOR` is 0, which is what makes the removal legal; `tools/abi/gen.py --diff-against <ref>` lists the twelve as `BREAKING` and exits 0 (`--strict` exits 1; no CI step runs either). Migration: at prepare, call `anira_tensor_init_host_planar(&block, channels, num_channels, ANIRA_DTYPE_F32, 2, shape)` once over the channel-pointer array with `shape = {num_channels, max_block}`; per callback store `block.shape[1] = n` and call the tensor entry of the same name. `_inplace` is `anira_handler_process(h, &block, &block, i, &delivered)`: in place is the same tensor as input and output. Separate buffers are two tensors, the input's over `const float* const*` with `ANIRA_TENSOR_READ_ONLY` ORed into `flags`. A `_multi` form takes one tensor per slot, `[1, values]` for a Static slot and an empty tensor (`shape[1] == 0`, NULL planes legal) for a slot the call leaves out, and `num_inputs` / `num_outputs` must be the handler's slot counts, where the float forms accepted a NULL pointer at a request of 0. The tensor borrows the pointer array and reads it at each call, so a host that rewrites the pointers in that array needs nothing else; a host whose array itself moves between callbacks fills the tensor in the callback, which is legal there (the factory is a field fill, `ANIRA_NONBLOCKING`). `delivered` replaces the `num_out` protocol: a nullable pure out parameter (an array of `num_outputs` counts in the multi forms), `shape[1]` of each output on `ANIRA_OK`, 0 on `ANIRA_MISSED` and on a failure, never read; the request is `shape[1]` of the output tensor, which no call writes, so a miss leaves nothing to refill. The latched log records name the tensor entry (`anira_handler_process: handler not prepared`). Gone with the entries: `anira_handler::m_float_adapter`, the float32 ring refusal of the float forms (a tensor of another dtype than its slot's is `ANIRA_ERROR_CONFIG`, as before) and the `### Fixed` entry of this cycle about `num_out` after a miss, which described an API this release does not contain. `anira::PlanarFloatAdapter` stays: the 2.x `anira::InferenceHandler` presents its channel pointers through it. Tests: the `test_abi` suites call the tensor entries through one helper, `test/abi/float_face.h` (`planar_f32()`, `empty_planar_f32()`, and `FloatFace`, which owns a `PlanarFloatAdapter`); `AbiHandlerCopyOracle` reproduces its six recorded transcripts through the tensor entries with `handler_copy_oracle_golden.h` byte-identical (the driver reproduces `num_out=[..]` of the recorded multi calls and says so); three cases are re-pointed (`AbiPrepare.TensorsBuiltOnceSurviveAMiss`, `AbiHandlerTensorMiss.AFloatHostsPlanarTensorsReachTheMissFunctionAsTheyAre`, `AbiHandlerTensor.APlanarAndAnInterleavedBlockAgreeBitForBitAcrossMisses`) and `TensorStems.TheFloatAdapterNullsThePlanesOfASlotACallDidNotCarry` pins the adapter's rule without the C entries.

## [v3.0.0-alpha.1] - 2026-09-03

## [v2.3.0] - 2026-09-02

anira v2.3.0 is the last release of the 2.x line. Development continues on the v3 branch (the versioned C ABI, `docs/anira-v3-architecture.md`); 2.x receives fixes only.

### Added

- One-sided streaming (#98, #99, #110): generators are driven by output demand, analysers read through `PrePostProcessor::get_output()`, and the `HostConfig` reference stream may be an input or an output (`m_tensor_is_input`, `HostConfig::k_first_streamable`). - `LatencyCalculator` (#66) replaces `SessionElement`'s latency arithmetic: closed forms instead of the LCM loop, `is_feasible()`, correct struct and ring sizing for fractional and smaller host blocks. Derivation in `docs/sphinx/latency.rst`.

- **Breaking:** the `InferenceConfig::Defaults` compile-time constants were renamed from the `m_` prefix to the `k_` prefix to match the constant-naming convention (`m_warm_up` → `k_warm_up`, `m_session_exclusive_processor` → `k_session_exclusive_processor`, `m_blocking_ratio` → `k_blocking_ratio`). The mutable `Defaults::m_num_parallel_processors` is unchanged.
- LiteRT is now the default TensorFlow-Lite-family backend. The legacy TensorFlow Lite backend (the older `TfLite*` C API, `ANIRA_WITH_TFLITE`) is the **same runtime** exposed through a different C API, so the two are now **mutually exclusive** — enable the legacy path with `-DANIRA_WITH_LITERT=OFF -DANIRA_WITH_TFLITE=ON`.
- `nlohmann_json` is now consumed as a release download instead of a git submodule.
- CMake options and their validation were consolidated inline into `CMakeLists.txt` (`AniraOptions.cmake` and the redundant linkage knob were dropped).
- `anira::calculate_min` / `anira::calculate_max` are now `inline` free functions instead of `const auto` lambdas (source-compatible: existing call sites and uses as a callable are unaffected)
- The internal logging helper `isLoggingEnabled()` was renamed to `is_logging_enabled()`
- Migrated the shared clang configs (`.clang-format`/`.clang-tidy`/`.clangd`) from the `tanh-lib` submodule symlinks to [`tanh-tooling`](https://github.com/tanh-lab/tanh-tooling) (pinned `v0.1.4`): committed as real files, kept in sync by the `clang_check.yml` drift check, and the now-unused `tanh-lib` submodule was removed (configs are byte-identical, so lint/format results are unchanged)
- Adopted the default Claude Code config: `.claude/settings.json` now enables the `tanh-tools` plugin from the tanh-tooling marketplace (its format/lint/type-check hooks supersede the previous bespoke `.claude/hooks`)
- CI now covers Windows-`arm64`, Linux-`aarch64` and macOS-`universal` legs (shared + static) in addition to the mobile workflow.

### Fixed
