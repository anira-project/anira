## [v3.0.0-alpha.3] - 2026-11-06

The Hard contract's defaults run: a measured budget and the `UNTIL_STABLE` warm-up pass, which times every plan at prepare, keeps the model's figure for later prepares and reports each plan's real-time factor and verdict (`anira_plan_info.rt_verdict`) for a host to act on ("Try nonetheless"). Model tensors run in any of the ten dtypes anira names, every built-in engine binds in place where its runtime accepts it, and the plan report states per slot and direction what the edge costs and who moves the bytes (ABI 0.3: 228 promised names, 4 draft, 12 Emscripten-only; `anira_check_abi` accepts the exact ABI version alone).

Refused at prepare: the Async contract, a Buffer spec under a Hard contract, a host domain other than `ANIRA_DOMAIN_HOST`, a transposing tensor layout. Not run yet: device blocks (every context is Host-only), model tensors with quantisation parameters at the boundary (refused at load); the GPU and draft tensor factories are field fills. npm: `@anira-project/anira` 3.0.0-alpha.3 on `next`.

### Added

- **TypeScript:** `ContractHandle.hardBudget(kind, explicitMs)`, `hardWarmup(mode, iterations)` (`anira::ContractHandle::hard_budget` / `hard_warmup`), `HardContractOptions.warmup`; a warm-up before `ready()` is refused; a JavaScript processor's `anira_processor_desc.id` is its defined name, so pages defining it share the figure.
- **The model's figure:** the core keeps each warm-up measurement per loaded model, engine id (per object for `anira.v2.custom`) and processor hooks while it lives, so two instances of the same plugin (same model, processor and engine id) report the same latency; a later prepare reuses it and runs no pass (`ANIRA_WARMUP_OUTCOME_REUSED`, logged with its age), and one whose every plan reuses its figure needs no running thread; two prepares of one model at once measure it once, a FIXED figure is remeasured under a stronger warm-up, `ANIRA_WARMUP_NONE` ignores it; processors of one tail field `anira_processor_desc.id` share it (`anira::Processor(std::string id)`, `Processor::id()`), else one with `before_inference` / `after_inference` measures per registration.
- **C ABI, handler:** `anira_plan_info` tail fields `warmup_iterations`, `warmup_outcome` (`anira_warmup_outcome`: `NONE`, `FIXED`, `STABLE`, `CAPPED`, `REUSED`), `measured_ms` / `median_ms` (max and median of the last four inferences), `rt_factor` (inference time / anchor hop period), `rt_parallel`, `rt_verdict` (`anira_rt_verdict`: `UNMEASURED`, `COMFORTABLE` at a load (`rt_factor / rt_parallel`) < 0.75, `MARGINAL` < 1, `NOT_REALTIME`), in `ANIRA_PLAN_INFO_INIT`; logged at prepare (Warning: a marginal or not real-time plan, a pass unsettled after 32, an explicit budget below the measurement, a pool that cannot keep up; the budget marked measured or explicit); TypeScript `PlanInfo.warmupIterations`, `warmupOutcome`, `measuredMs`, `medianMs`, `rtFactor`, `rtParallel`, `rtVerdict` and the two enums.
- **The MEASURED budget and the UNTIL_STABLE warm-up:** `anira_handler_prepare` times ordinary inferences of every plan on the inference threads (hooks and engine call, not the wait); MEASURED sets each `anira_plan_info.budget_ms` to the max of the last four and sizes the session for the slowest plan; the session is sized again after the pass (the stream starts over, nothing of the pass reaches it or a State pair; engines and processor re-prepared if the entry count moves); an explicit budget only reports them; UNTIL_STABLE (default) stops when the last four lie within 20 % of their median or one clock step, at most 32; FIXED n runs n; without a running inference thread `ANIRA_ERROR_INVALID_STATE` (also for an inference over 10 s); a failed inference `ANIRA_ERROR_ENGINE`.
- **Model tensors of any dtype anira names:** `ANIRA_DTYPE_F32`, `F64`, `F16`, `BF16`, `I8`, `U8`, `I16`, `I32`, `I64`, `BOOL8` (no longer float32 alone), any role, carried in the spec's dtype end to end (ring, Static store, State pair, engine calls); another dtype (several lanes, unsigned above 8 bits) is `ANIRA_ERROR_NOT_SUPPORTED` at `anira_handler_create`; nothing converts: another host type goes in `ring_dtypes`, with a processor converting in `pre_process` / `post_process`.
- **C ABI, handler:** `anira_plan_slot` tail fields `dtype` (the model tensor's) and `ring_dtype` (0 without a ring), logged; TypeScript `PlanSlot.dtype`, `ringDtype`.
- **C ABI, handler:** `anira_plan_slot` tail fields `window_derived` (1 if derived), `window` (elements along Time per inference, a flexible one as pinned) and `hop` (window less overlap), 0 on Static and State slots, the same in every plan, logged; TypeScript `PlanSlot.windowDerived`, `window`, `hop`.
- **C ABI, handler and context:** the enum `anira_mover_flags` (`ANIRA_MOVER_NONE` 0, `ANIRA_MOVER_ANIRA` 1: anira's code, an engine adapter's copy, `ANIRA_MOVER_ENGINE` 2: the runtime's code or API copy, a device provider's upload and readback, a registered engine; both bits where both move, the class then the worse move's) in `moved_by` of `anira_plan_slot` (tail field) and `anira_edge_info`, logged; the `ANIRA_MOVER_ANIRA` rows are exactly anira's per-inference copies; TypeScript `PlanSlot.movedBy`.
- **C ABI, handler and context:** the enum `anira_memory_kind`, which a device provider's edge class follows: `ANIRA_MEMORY_UNKNOWN` 0 (no probe established it; `ANIRA_EDGE_UNKNOWN`, refused by every edge-cost limit), `ANIRA_MEMORY_UNIFIED` 1 (host memory: CPU path, integrated GPU, Apple silicon, lavapipe; `ANIRA_EDGE_UNIFIED_TRANSFER`), `ANIRA_MEMORY_DEDICATED` 2 (device memory across a bus; `ANIRA_EDGE_DEDICATED_TRANSFER`), in `memory_kind` of `anira_edge_info` and `anira_plan_info` (tail field), logged; TypeScript `PlanInfo.memoryKind`.
- **C ABI, handler and context:** the kind is probed with no link dependency through Metal `hasUnifiedMemory`, Vulkan's device type and memory, CUDA `CU_DEVICE_ATTRIBUTE_INTEGRATED`, HIP `hipDeviceAttributeIntegrated` (5.0+), OpenCL `CL_DEVICE_HOST_UNIFIED_MEMORY`, D3D12 `D3D12_FEATURE_DATA_ARCHITECTURE.UMA`, on ONNX Runtime's `device_id` (default 0; CUDA, TensorRT, ROCm, MIGraphX, DirectML), the Metal default device (Core ML, MPSBackend) or, for WebGPU, LiteRT `gpu` and Vulkan, every device of the API the runtime picks among (Metal on Apple, D3D12 on Windows, Vulkan elsewhere, OpenCL for LiteRT on Android; unknown unless all agree); the web, NPUs and custom providers are unknown; asked lazily, off the audio thread, once per context (5 s timeout) until `anira_context_probe`, logged at Debug (`anira.system`); `ANIRA_TEST_MEMORY_KINDS` asserts a known machine's kinds in the tests.
- **C ABI, engines:** a registered engine states each slot's edge after each load, inputs first: `anira_engine_edge` (`edge_class`, `reason`) from `anira_engine_edge_fn` in the tail field `anira_engine_desc.edge` overwrites the provider rule's (NULL keeps it); the mover follows from the class (the engine whatever moves, none on `ANIRA_EDGE_ZERO_COPY`); a refusal fails the prepare with its status, an unnamed class with `ANIRA_ERROR_ENGINE`; C++ `anira::EngineEdge`, virtual `Engine::Loaded::edge(is_input, slot, provider_rule)` (base: the rule).
- **Web:** `HardContractOptions.edgeCost` / `ContractHandle.edgeCost` (`anira::Hard::edge_cost`, `anira::ContractHandle::edge_cost`; unset or `edgeCost(undefined)`: no limit); `EngineOptions.edge` (`EngineEdges`, `{ inputs?: EngineEdge; outputs?: EngineEdge }`) at `Pipeline.addEngine`, per direction (unset keeps the provider rule); `addEngine(ONNXRUNTIME_WEB_ENGINE_ID)` states `ANIRA_EDGE_COPY` by the engine both ways, `ONNXRUNTIME_WEB_ENGINE_EDGES` (root, scope and engine entries) for another id; a given `edge` replaces them.
- **Bundled models:** example-models `28e6dd9` (`extras/fetch-models.cmake`, was `d1bc5cf`): TypedGainNetwork at `int16`, `int8`, `float16` (cast at the boundary), a row per engine (`extras/models/model-pool/typed_gain_<dtype>.model.json`) and an ExecuTorch export at a static 512-sample window with caller-owned I/O (`typed_gain_<dtype>_unplanned.model.json`); an ONNX model per dtype (`dtype_matrix_<dtype>.onnx`); a fully integer TFLite model (`quantized_gain_network_int8.tflite`); in `extras/models/model_files.h`; for ONNX Runtime 1.26.0, TFLite 2.17.0, LibTorch 2.12.0, ExecuTorch 1.3.1.
- **Engines:** every built-in engine carries the ten dtypes (ONNX Runtime via the untyped `Ort::Value::CreateTensor`); quantised I/O (TFLite, LiteRT `LiteRtGetQuantizationTypeId`, torch, ExecuTorch `QInt8`, `QUInt8`, `QInt32`, `QUInt4x2`, `QUInt2x4`) is `ANIRA_ERROR_NOT_SUPPORTED` at load, never plain integers; ONNX int8 I/O is plain integers.
- **Docs:** the dtype guide (`usage/dtypes`, and the engine, processor, getting-started, architecture and web pages); `anira_tensor_spec_set_state_source` (`anira/abi/config.h`) no longer calls other tensors float32.
- **Web:** a JavaScript engine's tensor views (`engineTensors`, `EngineTensorView`) carry `dtype` and `data`, a typed array of the dtype over its memory (`Uint16Array` for float16 and bfloat16, bytes for bool8; `f32` stays); a bool8 Static input takes numbers (nonzero is 1); an audio node refuses a model of another dtype.
- **Web:** the ONNX Runtime Web engine runs every dtype (was float32 only), copied byte for byte (onnxruntime-web 1.25.1); a dtype unlike the model's element type is `ANIRA_ERROR_CONFIG`; its warm-up uses the model's types.
- **Web:** `HardContractOptions.ringDtypes` (`anira::Hard::ring_dtypes`) and `ContractHandle.hardRingDtype` (`hard_ring_dtype`) name a ring dtype per Streamed tensor.

### Removed

- `anira_handler_prepare`'s `ANIRA_ERROR_NOT_SUPPORTED` refusals of `ANIRA_BUDGET_MEASURED` and `ANIRA_WARMUP_UNTIL_STABLE`, a fresh contract's defaults.
- **Breaking:** C ABI — `ANIRA_EDGE_DEVICE_COPY` (1) and `ANIRA_EDGE_HOST_COPY` (2) of `anira_edge_class`: a copy within one domain is `ANIRA_EDGE_COPY`, a CPU–device crossing `ANIRA_EDGE_UNIFIED_TRANSFER` (unified memory) or `ANIRA_EDGE_DEDICATED_TRANSFER` (a bus). Migration: `ANIRA_EDGE_COPY`; a device provider's former `ANIRA_EDGE_HOST_COPY` row is the transfer its `memory_kind` gives.
- **Breaking:** C ABI — `ANIRA_EDGE_UNAVAILABLE` of `anira_edge_class`: a row's `available` (with `reason`) says whether its edge exists, an unavailable row names the class it would provide, and a pair without a row is `ANIRA_ERROR_EDGE_UNREACHABLE`. Migration: test `anira_edge_info.available` where code compared `edge_class` with `ANIRA_EDGE_UNAVAILABLE`.
- **Breaking:** C ABI — the enum `anira_edge_cost` (`ANIRA_EDGE_COST_PERMISSIVE`, `ANIRA_EDGE_COST_STRICT`) and its words `"permissive"`, `"strict"`; the edge cost is an `anira_edge_class` threshold; the migration is under Changed.

### Fixed

- **Core:** the model's figure keys a model given as bytes by a 64-bit content hash of the bytes (XXH64, computed once per bytes object) and their size, not by their owner, so two configs that borrow or copy the same model bytes (two instances of the JUCE example over its BinaryData) share one figure and latency.
- **Docs:** `anira/abi/draft/tensor_platform.h` is included by `anira/anira_all.h`, not `anira/anira.h`; `anira_tensor_spec_create`'s name binds a named engine side's slot the entry's tensors record leaves unnamed, and a custom engine's load record carries it.
- **Breaking:** C++ — an `anira::Processor` of `before_inference` / `after_inference` alone needs no `ANIRA_PROCESSOR_FLAG_REALTIME_PRE_POST` under a Hard contract (prepare refused it, `ANIRA_ERROR_CONFIG`): `Pipeline::add_processor` fills the reset slot only for the new phase bit `anira::Processor::k_reset` (`phase_bit(ANIRA_PHASE_RESET)`, in `k_all_phases`), `k_pre_process` or `k_post_process`. Migration: a processor without pre/post-process whose `Prepared` overrides reset adds `k_reset` to `phases()` (and keeps the flag), or its reset is not called.
- **LibTorch:** each thread that runs a model sets the engine's single intra-op thread, not the control thread alone; on Linux x86_64 (OpenMP) a oneDNN primitive (the stateful RNN's LSTM) spun one thread per core beside the inference threads.
- **Core:** the inference queue no longer preallocates ~329 MiB per process from `anira_context_create` on, nor 8 MiB per handler (#200; #207 on the web): each handler reserves room for its struct pool at prepare, off the audio thread, whose `try_enqueue` still never allocates.
- **Core:** a handler's prepare or destroy no longer zero-fills the other handlers' queued inferences beyond 1,024 (#200); its drain requeues them with the allocating enqueue, on the control thread.
- **Core:** a stateful handler no longer zero-fills a call's chunks once more than 33 to 64 wait their turn (#199): its pending queue is reserved at prepare for the whole struct pool.
- **ExecuTorch:** the engine's first init shrinks the runtime's process-wide thread pool to the calling thread (`ThreadPool::_unsafe_reset_threadpool(1)`): a kernel outside the XNNPACK delegate reached it through `parallel_for` despite `NoThreadPoolGuard` and started a worker per further core, which outlived every anira object; a statically linked binary that is unloaded (a Windows plugin) joined them in the pool's static destructor inside `FreeLibrary`, under the loader lock, and the unload never returned (`LibraryUnload.UnloadWithLiveSessionIsJoinedByHook` on the static Windows legs, once every executor ran its creation warm-up).
- **C ABI, handler:** a chunk a core queue has no room for (the inference queue, an exclusive handler's pending queue, a drain's requeue) sets `anira_handler_rt_error` to `ANIRA_ERROR_CAPACITY` like a dropped hop, not `ANIRA_OK`, and stays zeros at its stream position.
- **Latency:** a Static or State output no longer rounds the outputs' latency up to whole hops (#235): only Streamed outputs are synchronized, one alone keeps its figure, a non-streamed one reports 0; `stateful_accumulator`, the stateful RNN and RAVE report and prime less where the inference queue is not whole hops.
- **Latency:** several Streamed outputs meet on the grid of 1/g hops (g the gcd of their hops), at the least coherent figure at or above each ⌊P_i Λ⌋, not at whole hops; equal hops keep their figures. `anira_handler_get_latencies` and the rings' priming only go down; a declared latency (`anira_contract_hard_set_latency`, `"latencies"`) is untouched.
- **Processor:** `anira_processor_default_post_process` reads an output as `anira_processor_default_pre_process` lays out an input, `channels × window`, and pushes each channel's newest hop; as `channels × hop` it mixed channels or pushed late an output with an overlap (`anira_tensor_spec_set_window`). A version 2 document whose output exceeds its `postprocess_output_size` gets such an overlap (the 2.x `PrePostProcessor` keeps the 2.x push).
- **Web:** the ONNX Runtime Web engine's plan rows (`addEngine(ONNXRUNTIME_WEB_ENGINE_ID)`) say `ANIRA_EDGE_COPY`, moved by the engine, not `ANIRA_EDGE_ZERO_COPY`.
- **C ABI, handler:** an ONNX Runtime plan on a device execution provider (CUDA, TensorRT, ROCm, DirectML, CoreML, WebGPU) reports its slots moved by the engine at the class of the device's memory kind, as its capability row does, not `ANIRA_EDGE_ZERO_COPY`.
- **C ABI, configuration:** `anira_tensor_spec_create` refuses a dtype of 0 (`ANIRA_ERROR_INVALID_ARGUMENT`); `anira_model_config_to_json` refuses a dtype without a model-file word (`ANIRA_ERROR_NOT_SUPPORTED`), where it wrote `"float32"`.
- **Docs:** `anira_model_config_model_path` returns NULL for an entry without a source too (`anira_model_config_add_model_path` with NULL, `ModelConfig::add_model(engine_id)`); `anira::ModelConfig::model_path` throws `ANIRA_ERROR_INVALID_STATE` for both pathless kinds and `ANIRA_ERROR_INVALID_ARGUMENT` out of range; `anira_em_audio_node_create` lists a Streamed slot's non-float32 ring dtype under `ANIRA_ERROR_CONFIG`.
- **Docs:** a chunk's `entry` (`anira_processor_ctx.entry`, `anira_engine_ctx.entry`, `anira_prepare_info.num_entries`, `anira::EngineContext::entry`) is its position in the handler's chunk pool, not the core's job queue.
- **Docs:** `anira_handler_prepare` keys a registered engine's figure by its id (`anira.v2.custom` by its engine object), and `anira_contract_create_hard` / `anira_contract_create_async` name no edge-cost limit (`ANIRA_EDGE_UNKNOWN`) as their default, not the removed `PERMISSIVE`; `anira/compat/v2.hpp`'s `anira::v2::ContextConfig` and `anira::v2::Context` name v2.3.0's classes alone.
- **Examples:** a JUCE or CLAP backend choice without a plan (an engine the build lacks, such as ExecuTorch in a shared build) kept the previous plan running while the parameter showed the choice; the list no longer offers it, and a choice whose engine cannot run the model on the machine runs the bypass plan and says so (#243).

### Fixed

- Stateful in-order dispatch (`session_exclusive_processor = true`) no longer allocates on the audio thread — `SessionElement`'s pending-dispatch queue is now pre-sized and fed through an explicit producer token.
- Web: the audio worklet now polyfills `performance.now()` before the WASM module loads, fixing a `ReferenceError` (observed in Firefox) whenever a blocking-ratio deadline was read from the audio thread.
- The advanced benchmark no longer instantiates ONNX Runtime for the stateful RNN model, whose fixed 2048-sample ONNX export failed warm-up at other buffer sizes.
- Use-after-free when a pooled backend processor outlived the session that created it — `InferenceConfig` is now owned per-processor instead of aliasing the originating session's copy.
- Windows build failure in `Context::get_instance()` caused by `<windows.h>`'s `min`/`max` macros mangling an unrelated `std::min(...)` call; fixed by defining `NOMINMAX`/`WIN32_LEAN_AND_MEAN` before the include.
- Hardened `SessionElement::m_is_non_real_time` to `std::atomic<bool>` and unified the two `new_data_request()` wait paths onto one `wait_for_completion()` helper — previously a default-`blocking_ratio` session in non-real-time mode could free an in-flight buffer while the inference thread was still writing to it. Non-real-time mode also now works on WebAssembly once an inference worker is running.

## [v2.2.0] - 2026-06-23

### Added

- **Android support** (`arm64-v8a` + `x86_64`): the library, the prebuilt backends, and the full gtest suite running on a KVM-accelerated emulator, all wired into CI (`build_test_mobile.yml`). The glibc-only `pthread_*inheritsched` / `pthread_setattr_default_np` calls are gated behind `!__ANDROID__` (bionic lacks them) while keeping the portable `SCHED_FIFO` path.
- **iOS support** (device + simulator): the library and prebuilt backends shipped as an xcframework, with the full gtest suite running on the simulator in CI. Per-SDK xcframework slice selection; TFLite is consumed as a `TensorFlowLiteC.framework` via a generated shim so anira's `<tensorflow/lite/...>` includes resolve untouched.
- **LiteRT inference backend** (`anira::InferenceBackend::LITERT`): runs `.tflite` models through Google's native `LiteRt*` C API / CompiledModel runtime. Enabled by default (`ANIRA_WITH_LITERT=ON`) as the modern TensorFlow-Lite-family backend; wired into the examples and benchmarks.
- Data-driven backend downloads: prebuilt backends are fetched at configure time from the [`anira-project/backends`](https://github.com/anira-project/backends) release, pinned by `ANIRA_BACKENDS_VERSION`.
- Live backend integrity check: when GitHub is reachable, anira fetches each asset's published SHA256 and re-downloads any backend whose archive changed upstream or downloaded incompletely, instead of a committed hash lock. `ANIRA_BACKENDS_SKIP_REMOTE_CHECK=ON` skips the remote query for offline/reproducible builds.
- Bring-your-own-backend knobs: `ANIRA_<ENGINE>_ROOTDIR` (prebuilt tree), `ANIRA_<ENGINE>_URL` + `ANIRA_<ENGINE>_SHA256` (custom source), and per-engine `ANIRA_<ENGINE>_LINKAGE=shared|static`.
- clang-tidy conformance across the library, tests and benchmark sources, enforced in CI via the `tanh-lab/ci-actions/clang-tidy-check` action (`clang_tidy.yml`)
- `InstallConsumer` smoke test that builds against the installed package to catch packaging regressions.
- Release pipeline now publishes every tested arch×linkage artifact with backend-consistent naming: Android (static), iOS (xcframework), and Linux/macOS/Windows × `shared`/`static`, including macOS `universal`.

### Changed

- **Breaking:** the `InferenceConfig::Defaults` compile-time constants were renamed from the `m_` prefix to the `k_` prefix to match the constant-naming convention (`m_warm_up` → `k_warm_up`, `m_session_exclusive_processor` → `k_session_exclusive_processor`, `m_blocking_ratio` → `k_blocking_ratio`). The mutable `Defaults::m_num_parallel_processors` is unchanged.
- LiteRT is now the default TensorFlow-Lite-family backend. The legacy TensorFlow Lite backend (the older `TfLite*` C API, `ANIRA_WITH_TFLITE`) is the **same runtime** exposed through a different C API, so the two are now **mutually exclusive** — enable the legacy path with `-DANIRA_WITH_LITERT=OFF -DANIRA_WITH_TFLITE=ON`.
- `nlohmann_json` is now consumed as a release download instead of a git submodule.
- CMake options and their validation were consolidated inline into `CMakeLists.txt` (`AniraOptions.cmake` and the redundant linkage knob were dropped).
- `anira::calculate_min` / `anira::calculate_max` are now `inline` free functions instead of `const auto` lambdas (source-compatible: existing call sites and uses as a callable are unaffected)
- The internal logging helper `isLoggingEnabled()` was renamed to `is_logging_enabled()`
- Migrated the shared clang configs (`.clang-format`/`.clang-tidy`/`.clangd`) from the `tanh-lib` submodule symlinks to [`tanh-tooling`](https://github.com/tanh-lab/tanh-tooling) (pinned `v0.1.4`): committed as real files, kept in sync by the `clang_check.yml` drift check, and the now-unused `tanh-lib` submodule was removed (configs are byte-identical, so lint/format results are unchanged)
- Adopted the default Claude Code config: `.claude/settings.json` now enables the `tanh-tools` plugin from the tanh-tooling marketplace (its format/lint/type-check hooks supersede the previous bespoke `.claude/hooks`)
- CI now covers Windows-`arm64`, Linux-`aarch64` and macOS-`universal` legs (shared + static) in addition to the mobile workflow.

### Fixed

- Potential use-after-free in `Buffer::malloc_channels()` when channel-pointer allocation fails
- Installed `nlohmann_json` config so `find_package(anira)` works against the installed package
- Disabled backends now compile to empty translation units (guarded `.cpp` bodies), and `minimal-onnxruntime` is self-sufficient in static builds
- Value-initialize the `const InferenceConfig` in the install consumer
- clang-tidy violations and a CLAP static MSVC runtime mismatch; preserve the anira-before-`JuceHeader` include order on MSVC; qualified `mem*` calls with `std::` and added `<cstring>`
- Windows shared-DLL copy, the examples target list, and arm64 LibTorch in CI
