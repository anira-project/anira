## 1. Principles

Each rule is enforceable; the enforcing gate (§2.O) is named in brackets.

1. **The C header set `include/anira/abi/*.h` is the library's only binary contract**, byte-identical for native shared, native static (plugins, iOS) and Emscripten; `anira.hpp` and the TS package are conveniences over it. [gate 4: the header set compiles as C11 on every CI leg; gate 5: a pure-C consumer links both library shapes]
2. **Every entry point is a directly exported `anira_*` C function with a frozen signature**; no function table, no `uintptr_t` handle, no exported C++ symbol from v3.0.0-alpha.2 on, on ELF, Mach-O, PE and Wasm alike. [gate 1: symbol baseline on ELF/Mach-O/PE; the `--emit-tsd` export diff on Wasm]
3. **The Hard path is frozen**: the `ANIRA_NONBLOCKING` entries `anira_handler_process/process_separate/process_multi/push_data*/pop_data*/reset` are one-line forwarders to the v2 code paths (`src/scheduler/InferenceManager.cpp:53-134`) and never wait; v2's in-callback wait (`blocking_ratio`, `set_non_realtime`) lives in the `_wait` twins, which are not `ANIRA_NONBLOCKING`. [the v2 suite runs through `anira.hpp`/`compat/v2.hpp` from alpha.2; the RTSan leg instruments only the NB entries]
4. **Nothing on an `ANIRA_NONBLOCKING` path allocates, locks, waits, formats into heap memory, touches thread-local storage, returns a heap object, or invokes a callback that may**; `rt_vsnprintf` into a fixed record is the one allowed RT formatting. On Wasm `thread_local` is forbidden in any code reachable from the Worker or the worklet. [gate 6: RTSan runtime over the NB entries; `-Werror=function-effects` on the consumer-shaped test targets; the Wasm layout test asserts `__builtin_wasm_tls_size() <= 1024`]
5. **RT data is fixed-layout POD with one `sizeof`/offset table on every target** (`ANIRA_PTR` pins every pointer slot to 8 bytes) and that table is committed data (`abi/layout-<major>.txt`) that only an ABI-major commit may change; everything with a lifetime is an opaque handle mutated by scalar setters. [gate 3: layout executable natively and under node, diffed against the committed table]
6. **No enum value, struct layout or function set depends on a build option**: `USE_*`, `ENABLE_LOGGING`, `ANIRA_VERSION` become PRIVATE at alpha.2 (`CMakeLists.txt:338-356` today); presence is a runtime query (`anira_enabled_backends`). [gate 4 compiles the header with no anira define at all]
7. **Errors are `anira_status` integers; `status < 0` is the only stable failure test; messages land in a caller-owned `anira_error`; exceptions stop in `src/capi/`.** No status objects, no thread-local last-error, no `errno`; `== ANIRA_OK` is not a stable test because a minor may add positive statuses. A failure that returns a status is not logged; a failure that cannot return one (real-time entries, anira-owned threads, void and destroy entries, sinks) is logged once at Error; a real-time contract violation does both, flagged and latched (`docs/anira-v3-error-and-log-strategy.md`). [gate 5; the exception firewall macro is the only way to define a C entry; `anira.hpp` and TS `Status` use `ANIRA_FAILED`]
8. **Append-only inside an ABI major**: new functions, enum values, extension revisions, `anira_em_*` companions and descriptor tail slots appended after the last v3.0.0 slot bump `ANIRA_ABI_MINOR`; a changed layout, signature, value, thread contract or RT class is an ABI major bump. [gate 2: abidiff bit 8 always fails; bit 4 fails unless `ANIRA_ABI_MINOR(HEAD) > ANIRA_ABI_MINOR(last tag)`; the Tier-1 abidiff fails on bit 4 regardless]
9. **Every declaration carries one thread tag from the fixed vocabulary of §4**, `[callback-safe]` as an additive property where it applies, and `ANIRA_NONBLOCKING` where the body is RT. [`tools/abi/scan_header.py` rejects an untagged declaration]
10. **tanh-lib, concurrentqueue and nlohmann_json are PRIVATE and invisible on every platform**: tanh_core's objects are absorbed into libanira, no public header includes them, logging crosses as a C callback, tanh-lib gets no C ABI. [`anira_exports` forbids `thl`, `moodycamel`, `nlohmann`; strict `anira_header_isolation`; `consumer_tanh_first` binds locally]
11. **JS never hand-computes a struct offset on the control path and never writes a struct field by hand**: every descriptor JS must produce has an `anira_em_*_init` or a scalar-setter twin; RT structs are read through generated `layout.ts`. [generated `enums.ts`/`layout.ts`/`exports_wasm.txt` diffed in `build_web.yml`]
12. **No struct-by-value parameter or return anywhere; no 64-bit integer in an `ANIRA_NONBLOCKING` declaration (allowlist: `anira_now_ns`); timeouts and deadlines are `double` milliseconds; indices and sentinels are `uint32_t`; sample and element counts are `size_t`.** [`scan_header.py` lint]
13. **Stability is declared once, at v3.0.0 (`ANIRA_ABI_MAJOR 3`)**; before it `ANIRA_ABI_MAJOR` is 0 (CLAP's "0.X.Y is development", `clap/include/clap/version.h:11-13`), every gate runs, abidiff is advisory. [`anira_check_abi` demands an exact match while major is 0]
14. **Unmeasured surfaces live in `include/anira/abi/draft/`** with their own baselines (`abi/symbols-draft.txt`, `abi/abidiff-draft.supp`), never included by `anira.h`; promotion moves a name between baselines and never renames it. [gate 1 tolerates the draft list in both directions]
15. **Every CMake change uses the existing tanh-tooling modules**; what they lack is an anira-local script under `anira/cmake/` (never `cmake/tanh/`, pin-owned) until a tanh-tooling tag after v3.0.0 that anira and tanh-lib re-pin together. [`config-check.yml` drift check]

## 2. Decisions A–R

### A. Header set, naming, export macro, what a static consumer links

**Decision.** Files installed under `include/anira/`:

| file | content | frozen at |
|---|---|---|
| `anira.h` | C11 umbrella: includes every `abi/*.h` below in dependency order, never `abi/draft/`; **exists from alpha.2** — through alpha.1 `include/anira/anira.h` stays the v2 C++ umbrella (`include/anira/anira.h:4-22`, the v2 suite and `test/header_isolation.cpp` include it) and the M1 headers are included per file | v3.0.0 |
| `anira_all.h` | `anira.h` plus `abi/draft/*.h` | — |
| `abi/export.h` | `ANIRA_API`, `ANIRA_CALL`, `ANIRA_NONBLOCKING`, `ANIRA_NOEXCEPT`, `ANIRA_DEPRECATED`, `ANIRA_INIT`, `ANIRA_PTR` | M1 |
| `abi/version.h`, `abi/build_info.h` | ABI constants and negotiation (hand-written, the one source CMake reads); semver triple configured from git | M1 / generated |
| `abi/status.h`, `abi/enums.h`, `abi/config.h`, `abi/log.h` | status codes and `anira_error`; every enum; config handles and descriptors; log sink | M1 |
| `abi/tensor.h`, `abi/machine.h`, `abi/thread.h`, `abi/stage.h`, `abi/handler.h` | RT PODs; machine, capabilities, lifecycle; user-driven inference threads; rings, stage and backend descriptors; pipeline, handler, Hard entries and their `_wait` twins | M2 |
| `abi/ticket.h` | Async entries | M3 |
| `abi/draft/*.h` | unmeasured platform arms (`anira_tensor_init_metal/iosurface/ahardwarebuffer/d3d12`), later `frame.h`; included by `anira_all.h` only | never (until promoted) |
| `anira_em.h` | Emscripten companion (§F, §M), body under `#ifdef __EMSCRIPTEN__` | with `anira.h` |
| `anira.hpp` | header-only C++20 wrapper (§L), declared not ABI-stable | — |
| `compat/v2.hpp` | `anira::v2::*` constructor shims and `anira::v2::PrePostProcessor` views (§K, §L); removed one minor after 3.0 | — |

Per-file headers exist so the abidiff baseline and "which file froze when" are readable per milestone. Naming: functions `anira_<object>_<verb>`, types `anira_<noun>` (`typedef struct anira_machine anira_machine;`, handles are `anira_machine*`, never `uintptr_t` as today's wrapper passes, `src/emscripten-wrappers/InferenceHandler.cpp:10-42`), enum constants `ANIRA_<ENUM>_<VALUE>` with `ANIRA_<ENUM>_FORCE32 = 0x7fffffff`, macros `ANIRA_*`. A nested `include/anira/abi/.clang-tidy` (`InheritParentConfig: true`, struct/enum-constant naming relaxed) keeps `clang_tidy.yml` green without touching the pin-owned root `.clang-tidy` (`tanh-tooling/install.sh:47-59` owns only `DEST` paths); `clang_tidy.yml`'s positive `SOURCES` list (`clang_tidy.yml:34-36`) gains `src/capi/` and `test/abi/` and drops `src/emscripten-wrappers/` when that directory is deleted.

```c
/* abi/export.h */
#if defined(__EMSCRIPTEN__)
#  define ANIRA_API __attribute__((visibility("default")))   /* + generated -sEXPORTED_FUNCTIONS (J6: `used` unnecessary) */
#elif defined(ANIRA_STATIC)                                   /* PUBLIC on static targets, symbol-policy.cmake:110-115 */
#  define ANIRA_API                                           /* hidden inside the embedding plugin */
#elif defined(_WIN32)
#  if defined(ANIRA_BUILDING)                                 /* PRIVATE, symbol-policy.cmake:109 */
#    define ANIRA_API __declspec(dllexport)                   /* dllexport IS the allowlist on PE, symbol-policy.cmake:178-180 */
#  else
#    define ANIRA_API __declspec(dllimport)
#  endif
#elif defined(__GNUC__) || defined(__clang__)
#  define ANIRA_API __attribute__((visibility("default")))    /* + version script from tanh_set_export_allowlist SYMBOL anira_* */
#else
#  define ANIRA_API
#endif
#if defined(_WIN32) && !defined(_WIN64)
#  define ANIRA_CALL __cdecl                                  /* CLAP_ABI, clap/include/clap/private/macros.h:20-26; fixed forever */
#else
#  define ANIRA_CALL
#endif
#if defined(__clang__) && defined(__has_attribute)
#  if __has_attribute(nonblocking)
#    define ANIRA_NONBLOCKING __attribute__((nonblocking))    /* verified clang 22 + emcc 4.0.23 in C11 and C++20 (judge V1); confirm on the clang-20 CI leg */
#  endif
#endif
#ifndef ANIRA_NONBLOCKING
#  define ANIRA_NONBLOCKING
#endif
#if defined(__cplusplus)
#  define ANIRA_NOEXCEPT noexcept
#  define ANIRA_INIT(type, ...) (type{__VA_ARGS__})
#else
#  define ANIRA_NOEXCEPT
#  define ANIRA_INIT(type, ...) ((type){__VA_ARGS__})
#endif
#define ANIRA_PTR(T, name) union { T* name; uint64_t name##_bits; }   /* 8-byte pointer slot on ILP32 and LP64; zero the struct before use */
#define ANIRA_DEPRECATED(msg) __attribute__((deprecated(msg)))       /* MSVC: __declspec(deprecated(msg)) */
```

`ANIRA_STATIC`/`ANIRA_BUILDING` keep coming from `tanh_apply_symbol_policy(anira EXPORT_PREFIX ANIRA)` (`CMakeLists.txt:292`; `tanh-tooling/cmake/symbol-policy.cmake:108-116`). `abi/export.h` does not include `<tanh/core/ExportMacros.h>` (today `include/anira/system/Exports.h:30`). The internal C++ classes keep `system/Exports.h` through alpha.1 (the v2 suite links the shared library); **at alpha.2 the internal `ANIRA_API` is redefined to nothing** (`system/Exports.h` becomes a private header whose macro expands to empty on every platform), because on PE `dllexport` is the allowlist and a decorated internal class would otherwise stay in `anira-3.dll`'s export table after the version script has stripped it from ELF/Mach-O. `ANIRA_NONBLOCKING` is gated on `__clang__` + `__has_attribute`, not on `ANIRA_WITH_RTSAN` (J5), and it also replaces the internal `ANIRA_REALTIME` (`include/anira/utils/RealtimeSanitizer.h:4-14`) so the internal and the public attribute are one definition.

What a static-embedded consumer links: `anira::anira` (archive) — self-contained, tanh_core's objects inside it (§N). The archive's `INTERFACE_LINK_OPTIONS` carry `--exclude-libs` for `libanira.a` and the engine archives (extending `cmake/aniraBackendHelpers.cmake:139-160`; the `libtanh_core.a` entry of `CMakeLists.txt:301-303` is dropped because no such archive is linked any more), so the plugin's own `tanh_set_export_allowlist(<plugin> SYMBOL clap_entry)` (`examples/clap-audio-plugin/CMakeLists.txt:50-51`) is the only export decision left; `anira_*` never appears in a plugin's export table unless the plugin lists it.

**Why.** Flat exports are what a static plugin binds, what the driver thread calls directly under `[[clang::nonblocking]]`, and what JS calls as `Module._anira_x` (`web/src/wrappers/InferenceHandler.ts:23-49`); a function table would be a second surface with no consumer on static or Wasm builds. Per-file headers cost nothing and make the freeze auditable per milestone; naming the umbrella only at alpha.2 keeps the v2 suite compiling through alpha.1 without a rename.

**Plan impact.** §6 gains a "6.1 C ABI conventions" subsection quoting `abi/export.h`; §10 replaces "ABI breaks entirely" (plan:885); §11 M1/M2 list the header files per milestone.

### B. Versioning

**Decision.** Two integers own the promise, independent of the semver triple:

```c
/* abi/version.h (hand-written, frozen; CMake reads these two lines with file(STRINGS ... REGEX) — one source) */
#define ANIRA_ABI_MAJOR 3                     /* 0 until v3.0.0; SOVERSION; MACHO compat major; DLL suffix */
#define ANIRA_ABI_MINOR 0                     /* +1 whenever anything is appended; never in a patch release */
#define ANIRA_MAKE_ABI_VERSION(major, minor) (((uint32_t)(major) << 16) | (uint32_t)(minor))
#define ANIRA_ABI_VERSION ANIRA_MAKE_ABI_VERSION(ANIRA_ABI_MAJOR, ANIRA_ABI_MINOR)
#define ANIRA_ABI_VERSION_MAJOR(v) ((uint32_t)(v) >> 16)
#define ANIRA_ABI_VERSION_MINOR(v) ((uint32_t)(v) & 0xffffu)
/* abi/build_info.h (configured by anira/cmake/version.cmake, see below) */
#define ANIRA_VERSION_MAJOR 3
#define ANIRA_VERSION_MINOR 0
#define ANIRA_VERSION_PATCH 0
#define ANIRA_VERSION_STRING "3.0.0-alpha.2-12-gabc123"
#define ANIRA_MAKE_VERSION(maj, min, pat) (((uint32_t)(maj) << 22) | ((uint32_t)(min) << 12) | (uint32_t)(pat))   /* Vulkan packing */
```

Runtime: `anira_abi_version()`, `anira_check_abi(uint32_t header_abi_version)` (the one negotiation call: `ANIRA_OK` iff same major and library minor ≥ header minor; exact match while major is 0; `ANIRA_ERROR_ABI_VERSION` otherwise), `anira_version()` (packed semver), `anira_version_string()` (git describe, static storage; replaces `anira_get_version()` of `src/emscripten-wrappers/InferenceConfig.cpp:28-30`), `anira_get_proc_address(const char*)` (NULL = not in this build; the feature-detection mechanism for `dlopen` hosts).

The promise inside ABI major 3, from v3.0.0: existing functions keep name, signature, semantics, thread tag and RT class; existing enum values and Tier-1 POD layouts never change; a minor may append functions, enum values (below `_FORCE32`), positive statuses, extension revisions, descriptor tail slots (after the last v3.0.0 slot, §C) and new `anira_em_*` companions, each bumping `ANIRA_ABI_MINOR`; a patch changes nothing in the header. Deprecation: `ANIRA_DEPRECATED("use anira_x")` plus a `**Deprecated:**` CHANGELOG entry; the symbol stays exported until the next major. Major bumps only for: an RT POD layout change, a removed or renamed function, a changed enum value, a changed thread or RT contract. Everything the plan lists as deferred-additive (plan:897) fits inside major 3.

CMake: `cmake/abi-version.cmake` reads `ANIRA_ABI_MAJOR`/`ANIRA_ABI_MINOR` from `abi/version.h` (`file(STRINGS ... REGEX "#define ANIRA_ABI_(MAJOR|MINOR)")`) — no second copy — and sets `SOVERSION ${ANIRA_ABI_MAJOR}` (today `SOVERSION ${PROJECT_VERSION_MAJOR}`, `CMakeLists.txt:291`), `MACHO_COMPATIBILITY_VERSION ${ANIRA_ABI_MAJOR}.${ANIRA_ABI_MINOR}` and `MACHO_CURRENT_VERSION ${ANIRA_ABI_MAJOR}.${ANIRA_ABI_MINOR}.${PROJECT_VERSION_PATCH}` so dyld refuses a library older than the one a client linked; `OUTPUT_NAME anira-${ANIRA_ABI_MAJOR}` when `TANH_BINARY_FORMAT STREQUAL "PE"` (`anira-3.dll`, `anira-3.lib`; PE has no soname); `aniraConfigVersion.cmake` `COMPATIBILITY SameMajorVersion` (today `AnyNewerVersion`, `cmake/install.cmake:375-379`). Debian runtime package `libanira3` follows from `tanh-tooling/cmake/package.cmake:78` (`${CPACK_PACKAGE_NAME}${PROJECT_VERSION_MAJOR}`), so semver major and ABI major are kept equal by policy from 3.0.0; during the alphas the package is `libanira3` around `libanira.so.0` and `find_package(anira 3.0)` accepts mutually incompatible alphas — accepted, `anira_check_abi` is the gate that matters then. Prerelease tags: `tanh-tooling/cmake/git-version.cmake:22-31` strips only the leading `v` from `git describe --tags --abbrev=0`, so after `v3.0.0-alpha.1` `project(anira VERSION 3.0.0-alpha.1)` (`CMakeLists.txt:78`) would fail; an anira-local `cmake/version.cmake` calls `tanh_git_version`, strips `-[A-Za-z].*$` from `TANH_VERSION_SHORT` for `project()` and `write_basic_package_version_file`, and keeps the full describe string for `ANIRA_VERSION_STRING` — lands in the first M1 PR, before the first alpha tag. The v2 cross-session version-string compare (`src/scheduler/Context.cpp:325-348`) is dropped: two static embeddings have two cores (`Context.cpp:129`) and cannot see each other, and inside one core every session shares one header.

**Why.** Static builds, the Wasm module and Windows have no soname, so a function-level negotiation must exist beside the soname (precedents §7); packing `(major << 16) | minor` keeps `anira_check_abi` one integer that TS compares without BigInt.

**Plan impact.** §10 (new paragraph "What is promised, and by which number"); §11 M1 (`cmake/version.cmake`), M6 exit ("freeze declared: `ANIRA_ABI_MAJOR 3`, baselines committed"); preamble.

### C. Extensibility mechanism and plan §1b

**Decision.** Three object classes, one mechanism each:

| class | mechanism | why |
|---|---|---|
| Tier-1 RT PODs: `anira_tensor`, `anira_sync_token`, `anira_memory_handle`, `anira_stage_ctx`, `anira_log_record`, `anira_error` | fixed layout, no `struct_size`, pinned `sizeof`, versioned by ABI major only; a new shape is a new struct plus new functions | copied through lock-free FIFOs (plan:11), read per block, or value-initialised by `anira::Result<T>`; no size switch, no chain walk |
| config objects: `anira_machine_config`, `anira_model_config`, `anira_tensor_spec`, `anira_contract`, `anira_job_options`, `anira_pipeline` | opaque handle + scalar setters/getters (ORT `SessionOptions` shape) | the layout never enters the ABI; JS builds a config with one call per field (today it needs libc++ vector layout, `web/src/wrappers/InferenceHandler.ts:201-212`) |
| Tier-2 descriptors handed once to a setter or filled by an enumerator: device blocks, `anira_log_desc`, `anira_stage_desc`, `anira_backend_desc`, extension payloads, `anira_edge_info`, `anira_plan_slot`, `anira_plan_ext` | `uint32_t struct_size` first; descriptors with callbacks are `{struct_size, abi_version, user_data, ...slots}` (CLAP puts `plugin_data`/`host_data` second, `clap/include/clap/plugin.h:42-44`, `host.h:10-12`); tail growth appends **after the last v3.0.0 slot**; the library reads/fills only inside `min(struct_size, sizeof(lib's))` | tail growth without `pNext`; `user_data`'s offset can never move; TS writes no field by hand (§F, §M) |

`abi_version` is the packed `ANIRA_ABI_VERSION` the host compiled against (CLAP `clap_version_t`-first, `clap/include/clap/entry.h:62`); it lets anira gate calls into an older host. Array enumerators take the caller's element stride explicitly — `(uint32_t element_size, uint32_t* count, T* out)`, `element_size = sizeof(T)` in C, `anira_sizeof(id)` from TS — and write `min(element_size, sizeof(lib's T))` bytes per element at that stride; scalar enumerators (`backends`, `domains`, `ext_kinds`) have no stride. `out == NULL` returns the count; a short buffer fills what fits and returns `ANIRA_INCOMPLETE`.

`pNext` chains are rejected: plan:189 is the inverse of a chain's skip-unknown contract. Plan §1b maps as: every extension kind is a public C struct whose first member is `anira_ext_header { uint32_t struct_size; uint32_t version; const char* kind; }`; `kind` is the JSON key (plan:164, `"entry"`), `version` is the layout revision (plan:165). **The registry key is `(kind, version)`** (CLAP's `name/REV` rule, `clap/conventions/extension-id.md:3-12`, with the revision as a field because the kind doubles as the JSON key): a new layout is a new row, tail growth within a revision uses `struct_size`, and a known kind with an unregistered version is rejected **at set time** with `ANIRA_ERROR_EXTENSION_VERSION` (both code and JSON can be checked there); in JSON the revision is the optional `"version"` member of the extension object (default 1). Setters: `anira_model_config_set_model_ext(cfg, model_index, hdr, err)`, `anira_tensor_spec_set_ext`, `anira_machine_config_set_ext`, `anira_contract_set_ext`, `anira_job_options_set_ext` (borrowed until `submit` returns), each with a `_set_ext_json(h, kind, utf8, len, err)` twin so JS registers extensions as strings. A known kind is deep-copied through its registry row; an unknown kind is stored as `{header, raw JSON text}` only (no clone is possible beyond the header) and `anira_handler_prepare` fails by name — `extension 'quant' on tensor 'audio_in' is not consumed by any stage in this build` — one failure point for code and JSON (plan:189). Every stage and backend declares what it consumes: `anira_stage_desc`/`anira_backend_desc` carry `const char* const* consumed_kinds; uint32_t num_consumed_kinds;` as v3.0.0 fields (plan:187), so the consumed-or-fail walk (plan:189) is over declared data. The registry (plan:180-184) is internal in v3.0.0: `{kind, version, struct_size, clone, destroy, from_json, to_json}`; `anira_registered_ext_kinds(count, out)` reports it (plan:193). **Third-party kinds are post-3.0**: an additive `anira_register_ext_kind` plus a prepare-time payload accessor arrive with the first external consumer; the reverse-URI prefix (`"de.tu-berlin.ak.mel"`) is reserved now so anira's bare kinds (`"entry"`, `"quant"`, `"ort_session"`) never collide. Reserved blocks written into `enums.h` now: backend engine bytes `0x01-0x7e` anira, `0x7f` custom; domain values `12-63` reserved for later domains; `anira_struct_id` `0x0001xxxx` extension payloads, `0x0004xxxx` Emscripten-only structs (WebGPU's Emscripten block, precedents §3).

**Why.** Opaque config + setters is the lowest-risk growth model for one developer and the thinnest TS layer; `struct_size` on descriptors is target-dependent (pointers) but they are handed to setters once, never read per block; the explicit stride is the one rule that makes `struct_size` growth usable for arrays without per-element pre-initialisation.

**Plan impact.** §1b: `ExtBase`/`Extensions`/`ExtInfo` C++ classes become the internal carrier behind the handles; the C struct and the setter pair are the public spelling; "struct layouts fixed for the life of a major" (plan:161) becomes "Tier-1 PODs fixed for the life of the ABI major; descriptors grow at the tail; extension layouts fixed per revision"; the third-party sentence moves to the post-3.0 list. §4, §5, §2, §3: each `Extensions ext` member becomes the `set_ext` pair; §7 stages gain `consumed_kinds`.

### D. Error model

**Decision.**

```c
typedef enum anira_status {
    ANIRA_OK = 0, ANIRA_SUCCESS_UPGRADED = 1 /* v2 JSON auto-upgraded */, ANIRA_INCOMPLETE = 2 /* enumeration buffer short */,
    ANIRA_TIMEOUT = 3, ANIRA_PENDING = 4,
    ANIRA_ERROR_UNKNOWN = -1, ANIRA_ERROR_INVALID_ARGUMENT = -2, ANIRA_ERROR_INVALID_STATE = -3, ANIRA_ERROR_OUT_OF_MEMORY = -4,
    ANIRA_ERROR_NOT_SUPPORTED = -5 /* backend/domain/kind not in this build */, ANIRA_ERROR_NO_SUCH_FILE = -6, ANIRA_ERROR_MODEL_LOAD = -7,
    ANIRA_ERROR_ENGINE = -8, ANIRA_ERROR_CONFIG = -9 /* prepare-time legality, plan:253 */, ANIRA_ERROR_EXTENSION_UNCONSUMED = -10,
    ANIRA_ERROR_EXTENSION_UNKNOWN = -11, ANIRA_ERROR_EDGE_UNREACHABLE = -12, ANIRA_ERROR_BUDGET = -13 /* Hard validation */,
    ANIRA_ERROR_CAPACITY = -14 /* RT: no free slot / ring full */, ANIRA_ERROR_TICKET_STALE = -15, ANIRA_ERROR_WRONG_CONTRACT = -16,
    ANIRA_ERROR_NOT_PREPARED = -17, ANIRA_ERROR_JSON = -18, ANIRA_ERROR_ABI_VERSION = -19, ANIRA_ERROR_BUFFER_TOO_SMALL = -20,
    ANIRA_ERROR_DEVICE = -21, ANIRA_ERROR_EXTENSION_VERSION = -22, ANIRA_ERROR_INTERNAL = -100, ANIRA_STATUS_FORCE32 = 0x7fffffff
} anira_status;
#define ANIRA_FAILED(s)    ((int32_t)(s) < 0)          /* the only stable failure test */
#define ANIRA_SUCCEEDED(s) ((int32_t)(s) >= 0)
#define ANIRA_ERROR_MESSAGE_CAPACITY 512
typedef struct anira_error { int32_t status; uint32_t reserved; char message[ANIRA_ERROR_MESSAGE_CAPACITY]; } anira_error;   /* Tier 1, 520 bytes, frozen */
#define ANIRA_ERROR_INIT ANIRA_INIT(anira_error, ANIRA_OK, 0u, {0})
```

Every fallible function returns `anira_status`; created handles come back through an `out` parameter; functions that can produce a message take `anira_error* err` (nullable) as their last parameter and fill it on failure. Positive statuses are informational successes (`ANIRA_SUCCESS_UPGRADED` so TS can surface the v2-JSON one-time warning; `ANIRA_INCOMPLETE` for the enumeration convention) and **the set of positive statuses a function may return is not frozen** — a minor may add one — which is why the stable idiom is `ANIRA_FAILED(s)` and never `s != ANIRA_OK` (§6.1 of the plan, the §9 sketches, `anira.hpp` and the TS `Status` helper all use it). RT entries never take `anira_error`: they return a count or an `anira_status`, log through the RT queue as v2 does (`include/anira/utils/Logger.h:123-134`), and record the last contract violation in a per-handler relaxed atomic readable through `anira_handler_rt_error(h)` (so a worklet learns why `process` returned 0 without a message channel). Exceptions never cross: `src/capi/*.cpp` wraps every control-path body in `ANIRA_CAPI_BEGIN/END` (`std::bad_alloc` → `OUT_OF_MEMORY`, `std::invalid_argument` → `CONFIG`/`INVALID_ARGUMENT`, engine exceptions such as `throw_if_foreign_onnxruntime` at `src/backends/OnnxRuntimeProcessor.cpp:43-55` → `ENGINE`/`MODEL_LOAD`, `...` → `INTERNAL`; out-params untouched on failure); RT bodies are `noexcept` with no catch (nothing inside them throws by the v2 contract). `anira_status_string(status)` returns static text. Ticket failures live on the ticket (`anira_handler_ticket_error`), not on the handler (plan:191). **The Wasm build keeps exception catching enabled** (`-sNO_DISABLE_EXCEPTION_CATCHING`, `cmake/detect-emscripten.cmake:13`, `cmake/build-wasm.cmake:55`): Emscripten's default compiles `throw` but disables every `catch`, so the firewall itself needs the flag (verified on emsdk 4.0.23); switching to `-fwasm-exceptions` is a size/speed choice once the ORT wasm archive is built with it (§7).

**Why.** A caller-owned fixed buffer works identically in a static plugin, in a `dlclose`d DSO and per Wasm instance; a thread-local buffer is per module instance on Wasm and the worker does run control-path calls (`web/src/workers/inferenceWorkerHandler.ts:143-166`); status objects allocate and need a release call from JS. A frozen `anira_error` lets `anira::Result<T>` value-initialise it without an `_INIT` and lets TS allocate it with `anira_sizeof(ANIRA_STRUCT_ERROR)` forever.

**Plan impact.** §6 (all "fails by name" sentences cite `anira_error.message`; new §6.1 states the `ANIRA_FAILED` idiom), §1b (plan:189, 191), §7 (plan:520, "fails prepare() with the recipe in the message"), §8 (loader failures are `ANIRA_ERROR_JSON` + message, never dropped entries as `src/utils/JsonConfigLoader.cpp:280-327` does today).

### E. Ownership and lifetime

**Decision.**
- Create/destroy pairs: `anira_status anira_<x>_create(..., anira_<x>** out, anira_error*)`; `void anira_<x>_destroy(anira_<x>*)`, NULL-safe, a second destroy of the same pointer is undefined. Config handles are value-like: a handler *copies* the pipeline and every config at `anira_handler_create` (v2 keeps `InferenceConfig&` for life, `include/anira/InferenceHandler.h:455`); configs and pipelines may be destroyed right after the call.
- Descriptor and bytes carriers are refcounted internally: `anira_pipeline_add_stage`, `anira_pipeline_set_custom_backend` and `add_model_bytes`/`set_model_bytes` wrap the descriptor or the `BORROW`ed bytes in a `std::shared_ptr` carrier that every copy (pipeline, handler, pooled `BackendBase` whose lifetime is decoupled from the handler, `include/anira/backends/BackendBase.h:99`, `src/scheduler/Context.cpp:441-487`; ExecuTorch keeps the blob for the instance, `src/backends/ExecuTorchProcessor.cpp:140-144`) shares; `release(user_data)` and `anira_bytes_release_fn` fire **exactly once, when the last carrier reference dies, on the thread that destroys it** — the caller of `anira_pipeline_destroy`, `anira_handler_destroy`, `anira_model_config_destroy` or the pool's release, all `[main-thread]`. A pipeline destroyed without ever creating a handler releases once; two handlers from one pipeline release once, after the second is destroyed. Pooled processors extend the bytes' lifetime by construction.
- Strings in: UTF-8, NUL-terminated, copied by the callee (paths widened internally on Windows). Strings out: `const char*` owned by the object and valid until it is destroyed or mutated, or `(char* buf, size_t cap, size_t* out_len)` with `ANIRA_ERROR_BUFFER_TOO_SMALL`; never on RT paths.
- Model bytes: `anira_bytes_ownership` = `ANIRA_BYTES_COPY` or `ANIRA_BYTES_BORROW` + optional `release(bytes, ctx)`; borrow is the plugin default (`tanh_add_binary_data` blobs live for the DSO, `tanh-tooling/cmake/binary-data.cmake:27`); v2 borrows binary blobs silently (`include/anira/InferenceConfig.h:103-114`), v3 says so.
- Tensor: `release` + `manager_ctx` exactly as plan:70-73. `release == NULL` = borrowed until the ticket is terminal (Async) or the call returns (Hard). For a user tensor with a non-NULL `release`: **one submit = one release call** — anira invokes it exactly once per submitted copy, on an inference thread when the job reaches a terminal state, inside `anira_handler_poll`/`ticket_wait` for Polled delivery, or on the calling thread of `anira_handler_destroy`/`anira_handler_prepare` for jobs still outstanding then; never on the driver thread. **Tensors obtained from `anira_handler_allocate_input/allocate_output` are anira-owned pool tensors and anira never invokes their `release`**: the producer submits the same descriptor repeatedly (plan:104 multi-buffering over `input_released`) and returns it with `anira_handler_free_tensor(h, t)` `[main-thread & prepared]`; `prepare` and `destroy` free every pool tensor still out. A JS-produced tensor is always borrowed (JS cannot supply a function pointer); the TS `Tensor` frees its heap block after a terminal `status()`.
- Sync-token fds (`ANIRA_SYNC_SYNC_FILE_FD`, `ANIRA_SYNC_OPAQUE_FD_SEMAPHORE`): the token owns its fd (plan:99). `anira_handler_submit` and `anira_handler_bind_output` take `anira_tensor*` (non-const) and **move** every owning `acquire` token into the slot: the caller's `acquire.kind` becomes `ANIRA_SYNC_NONE` and `u.fd` becomes `-1` before the call returns, so a later `anira_sync_token_reset` on the caller's copy closes nothing. Tokens read through `ticket_input_released/output_ready` are **non-owning views valid until `ticket_release`** (no `dup`, so the accessors stay `ANIRA_NONBLOCKING`); a caller that needs one longer calls `anira_sync_token_dup(src, out)` `[thread-safe, !audio-thread]`. `anira_sync_token_reset` closes an owned fd (`[thread-safe, !audio-thread]`). Owned fds inside a slot are closed by the inference thread when the slot is recycled (deferred close), never by `ticket_release`, which therefore stays `ANIRA_NONBLOCKING`; `anira_handler_destroy`/`prepare` close the rest on the calling thread. Other kinds are non-owning.
- Tickets are `uint32_t` values (`slot & 0xffff`, `generation << 16`; `ANIRA_TICKET_INVALID = 0`), never heap objects: `submit` never allocates, `anira_handler_ticket_release` marks the slot for recycling (a still-pending ticket's slot is recycled only after the job is terminal; the ticket value is invalid for the caller immediately), `ANIRA_ERROR_CAPACITY` after `lanes * max_in_flight + 8` unreleased tickets, `ANIRA_ERROR_TICKET_STALE` for a recycled slot.
- Machine: a refcounted **handle over the immortal core** (`include/anira/scheduler/Context.h:79-81`, one core per copy of anira). `anira_handler_create` adds a reference so the handle's memory (reconciled config, device blocks from M4, capabilities) outlives the user's `anira_machine_destroy`; `anira_machine_destroy` drops the user's reference, invalidates the handle for the caller regardless of the count, and **joins nothing**. Thread pool and inference queue are core-owned: the pool exists exactly while any handler in this copy exists (`Context.cpp:441-487`), user-driven `anira_inference_thread` objects bind to the core's queue and outlive machines (`Context.h:395-397`, `Context.cpp:1228-1236`). The first machine sizes the pool, later machines reconcile per field as today (`Context.cpp:303-405`: wait strategy first wins, log level most verbose, pool only shrinks, never to zero). `num_threads == 0` keeps the tree meaning "bring your own threads" (`ContextConfig.h:221-231`; the Wasm build depends on it, `src/emscripten-wrappers/InferenceHandler.cpp:15,26`); `ANIRA_THREADS_AUTO = 0xffffffff` is the library default (`hardware_concurrency()/2` natively, 0 on Wasm, `ContextConfig.h:175-182`) and the plan's intent at plan:330.
- Unload/shutdown, C-visible: `anira_status anira_shutdown(void)` = `Context::shutdown()` (`Context.cpp:682-704`, idempotent, never creates the core) **effective only when no machine handle and no handler exist in this copy**; otherwise it does nothing and returns `ANIRA_ERROR_INVALID_STATE` — so a client of a shared `libanira.so.3` cannot silence another client's sessions (CLAP's `init`/`deinit` counter, `clap/include/clap/entry.h:34-60`, protects one DSO, not a resource two DSOs share; §R). It is meant for static embeddings and is called from `clap_deinit`/`ExitDll` as `examples/clap-audio-plugin/anira-clap-demo-pluginentry.cpp:42-49` does today. `anira_release_core_if_idle()` and `anira_has_core()` stay. The ELF/Mach-O destructor hook (`Context.cpp:131-146`) stays as a **backstop for hosts that skipped `anira_handler_destroy`**; because v3 runs host code (`anira_backend_desc.process`, `before/after_inference`, `on_complete`, tensor `release`) on pool threads, a host that installs custom stages or backends must destroy its handlers before its DSO is unloaded — the hook joins under the loader lock and host code that binds symbols there deadlocks (v2's argument at `Context.cpp:139-143` no longer covers host code). Windows keeps the non-joining `UnloadGuard` (`Context.cpp:147-158`); `anira_machine_destroy` and `anira_shutdown` are tagged `[main-thread & !loader-lock]`. The `test/unload` death test is retargeted at the C ABI.
- Inference threads: user-managed `anira_inference_thread` objects must be stopped before unload (`Context.h:401`); the Wasm stop protocol is in §J/§M.

**Why.** Copy-at-create removes the reference-lifetime trap of v2 and lets TS free builders eagerly; refcounted carriers are the only way "release exactly once" is implementable over copies; integer tickets make `submit` allocation-free for a 33 ms render loop; moving fd tokens at `submit` is the only rule that avoids plan:99's double close.

**Plan impact.** §1 (plan:70-73, 99 unchanged in substance; the C names and the move-at-submit rule), §4 (plan:329-330 corrected: `0` = bring your own, `ANIRA_THREADS_AUTO` = auto), §6 (tickets as values; `allocate_*` never released by anira; `free_tensor`), §9 (teardown lines), §11 M2 (`test/unload` retarget).

### F. Callbacks

**Decision.** Convention: `void* user_data` is the **last parameter of every callback signature** and the **third member of every descriptor** (`{struct_size, abi_version, user_data, ...}`, §C); one slot (the C++ wrapper stores a heap control block, the JS bridge stores a registry key); every callback fires exactly once per event; re-entrant `submit` from `on_complete` is forbidden in v1. **`[callback-safe]` is an additive property**: from inside any callback a host may call exactly the functions tagged `[callback-safe]` in §3 — `anira_tensor_*` accessors, `anira_ring_*`, `anira_stage_default_*`, `anira_log_rt`, `anira_now_ms/ns`, `anira_handler_rt_error`, `anira_handler_ticket_status/input_released/output_ready/ticket_error/ticket_release` — and nothing else. The reason is a real lock: `anira_backend_desc.prepare` runs inside `create_session` under `m_lifecycle_mutex` (`Context.cpp:530-535`) and sync log records are dispatched while that non-recursive mutex is held (`Context.cpp:259-286, 303-405`), so a `prepare` or log callback that calls `anira_machine_create`, `anira_handler_create/destroy` or `anira_shutdown` deadlocks. `ticket_release` from `on_complete` is legal (the slot recycles after the callback returns); `submit` is not. Function-pointer typedefs on RT slots carry `ANIRA_NONBLOCKING` so `-Wfunction-effects` flags a blocking body in the consumer's own build (verified in C, judge V2).

| callback | thread tag | RT class | descriptor |
|---|---|---|---|
| stage `pre_process`, `post_process` | `[driver-thread]` under Hard, `[inference-thread]` under Async | `ANIRA_NONBLOCKING` | `anira_stage_desc` |
| stage `before_inference`, `after_inference` | `[inference-thread]` (between dequeue and engine call, `src/scheduler/InferenceThread.cpp:260-283`) | `ANIRA_NONBLOCKING` | `anira_stage_desc` |
| stage `prepare(anira_handler*, const anira_plan_report*, user_data)`, `release` | `[main-thread]` (the caller of `anira_handler_prepare`; `release` on the caller of the last destroy, §E) | may allocate; must not call lock-taking entries | `anira_stage_desc` |
| custom backend `process` | `[inference-thread]` | may block (engine call), must not allocate per call | `anira_backend_desc` |
| custom backend `prepare(const anira_model_config*, instances, user_data)`, `release` | `[main-thread]`, under the lifecycle mutex | may allocate; must not call lock-taking entries | `anira_backend_desc` |
| `on_complete` | `[inference-thread]` under `ANIRA_DELIVERY_IMMEDIATE`; the caller of `anira_handler_poll`/`ticket_wait` under `POLLED` | `ANIRA_NONBLOCKING` | `anira_job_options_set_on_complete` |
| log sink `anira_log_fn` | any thread that logs — the caller of every `[main-thread]` entry (sync records, `thl` `Logger.cpp:466-472`), the caller of `anira_machine_destroy`/`anira_shutdown` (final flush), `[drain-thread]` for RT records; never the driver thread; may run with anira's lifecycle lock held | not RT, may allocate, must not call anira | `anira_log_desc` |
| tensor `release`, model-bytes `release`, descriptor `release` | `[inference-thread]` or the caller of `poll`/`ticket_wait`/`prepare`/`destroy` (§E) / `[main-thread]` / `[main-thread]` | not RT | on the tensor / carriers |

A non-OK status from `pre_process` completes that chunk as zeros at its stream position (v2 `complete_with_zeros`, `src/scheduler/SessionElement.cpp:244-248`), records the status in `rt_error` and emits one RT log record; non-OK from `post_process` zeroes that chunk's outputs; non-OK from `before/after_inference` marks the job `ANIRA_TICKET_FAILED` (Async) or zeros (Hard).

WASM: JS cannot supply C function pointers without `addFunction`, which needs `ALLOW_TABLE_GROWTH` and a per-instance table in this no-pthread multi-instance build (`facts/anira-wasm-ts.md` §7.6). `anira_em.h` therefore ships trampolines: `anira_em_stage_desc_init(desc, js_key, hook_mask)` fills the six slots with C functions compiled into anira that forward through one `EM_JS` hook object, and `anira_em_pipeline_add_js_stage(pipe, domain_in, domain_out, js_key, hook_mask, err)` is exactly `anira_em_stage_desc_init` followed by the ordinary `anira_pipeline_add_stage` — the registration path is the same C function native uses. `hook_mask` (`ANIRA_EM_HOOK_PRE 1, POST 2, BEFORE 4, AFTER 8, PREPARE 16, RELEASE 32`) replaces the `m_js_inference_hooks` atomic gate (`src/emscripten-wrappers/JSPrePostProcessor.cpp:53,63,101`): an unset bit stays NULL and never crosses into JS. The hook object is `Module.anira = { version, stage(key, phase, a, b), backend(key, inPtr, nIn, outPtr, nOut, instance), log(recordPtr), complete(key, handlerPtr, ticket) }`, replacing the undocumented `Module.processPrePost`/`processBuffers` (`web/src/factory.ts:36-41`); phases 0-3 pass `a = ctxPtr, b = 0`, phase 4 (`PREPARE`) passes `a = handlerPtr, b = planReportPtr`, phase 5 (`RELEASE`) passes zeros; its layout is versioned by `ANIRA_EM_HOOKS_VERSION`, checked by `anira_em_hooks_version()` against `Module.anira.version` at instantiation. JS custom backends: `anira_em_backend_desc_init(desc, js_key)` leaves `prepare` and `release` NULL — readiness is the JS-side protocol that exists today (Worker `registerProcessor` → `await init()` → `'processorRegistered'`, `web/src/workers/inferenceWorkerHandler.ts:143-166`), which TS completes **before** calling `anira_handler_prepare`; `anira_handler_create` loads nothing for a `CUSTOM` candidate whose `prepare` is NULL. JS completion: the key travels with the job — `anira_em_job_options_set_on_complete_js(opts, js_key)` — so no completion can precede its registration; `Module.anira.complete` fires inside the Worker's blocked `run_loop` and TS forwards it to the main-thread `Ticket` by `postMessage`. Each hook fires on the JS thread whose module instance executes the C call (worklet for pre/post, worker for before/after and backend `process`, main for prepare/release), identical to today's phase routing (`JSPrePostProcessor.cpp:6-19`).

**Why.** One `user_data` slot suffices for C++ and JS and its fixed offset survives every tail growth; an additive `[callback-safe]` tag is the only form under which the callbacks the design requires (a stage reading its tensors, an `on_complete` releasing its ticket) are legal; the trampoline design keeps the C header free of Emscripten and the JS registry per instance.

**Plan impact.** §7 (`stage::Custom` and custom backends are descriptors with `consumed_kinds`), §6 (`JobCallback on_complete` → `anira_job_complete_fn`; the callback-safe list), §3 (`Delivery::Immediate` thread), new §9 TS sketch.

### G. Fixed-width types, pinned enum values, target layouts

**Decision.** Every enum is a C `enum` with explicit values and a `_FORCE32 = 0x7fffffff` terminator; enums appear as the enum type in parameters and as `uint32_t` fields in structs. `typedef uint32_t anira_bool;`. `anira_dtype` is a packed `uint32_t` = `code | bits << 8 | lanes << 16`, whose little-endian bytes are exactly DLPack's `DLDataType {uint8 code; uint8 bits; uint16 lanes}` (J1: a 4-byte struct is passed `byval` through a pointer on wasm32; a `uint32_t` is not). `anira_ticket` is `uint32_t`. Indices, slots, counts of tensors/channels and sentinels are `uint32_t` (`ANIRA_ANCHOR_FIRST_STREAMED = 0xffffffff`, `ANIRA_THREADS_AUTO = 0xffffffff`); sample and element counts are `size_t` (v2-identical on the Hard entries; a JS `number` on wasm32); durations/deadlines/timeouts are `double` milliseconds. **"Hot" is defined as every `ANIRA_NONBLOCKING` declaration**: no `int64_t`/`uint64_t` parameter or return there, with `anira_now_ns` as the one allowlisted exception (`scan_header.py` carries the list); `int64_t` otherwise appears only in config-time shape/window/extent setters (`BigInt` at config time only) and in the `anira_tensor` fields, which JS reads through `layout.ts`. Any `uint32_t`/`size_t` value ≥ 2^31 returned to JS arrives as a negative i32 and needs `>>> 0` — documented once in `web/src/runtime/Heap.ts` (judge V8), never claimed away.

Pinned values (independent of `USE_*`; today `enum InferenceBackend` values shift with the build, `include/anira/utils/InferenceBackend.h:32-110`, and the web wrapper exports `get_inference_backend_onnx()` to cope, `src/emscripten-wrappers/InferenceConfig.cpp:17-25`): see the header sketch §3 for the full list. Backend ids are `engine << 8 | execution provider` (`ANIRA_BACKEND_ONNXRUNTIME_CPU = 0x0101`, `_WEBGPU = 0x0102`, `_CUDA = 0x0103`, `_DIRECTML = 0x0104`, `LIBTORCH_CPU = 0x0201`, `LIBTORCH_CUDA = 0x0202`, `TFLITE_CPU = 0x0301`, `LITERT_CPU = 0x0401`, `EXECUTORCH_CPU = 0x0501`, `CUSTOM = 0x7f01`); v2 `ONNX` maps to `ONNXRUNTIME_CPU`; JSON strings become `"onnxruntime"`, `"onnxruntime:webgpu"` (plan:667) with the upper-case v2 names accepted on the upgrade path.

Layout rule: RT PODs are Tier 1 — every pointer sits in an `ANIRA_PTR` slot, every count is `uint32_t`/`uint64_t`, so `sizeof` and every offset are identical on wasm32, LP64 and LLP64: `anira_memory_handle` 24, `anira_sync_token` 24, `anira_tensor` 216, `anira_stage_ctx` 56, `anira_log_record` 56, `anira_error` 520 bytes (verified with clang 22 and emcc 4.0.23, `refute-wasm.md` §0). The table is committed as `abi/layout-<ABI_MAJOR>.txt` (struct id, `sizeof`, every `offsetof`), emitted by the layout executable and diffed by gate 3; the file may change only in a commit that changes `ANIRA_ABI_MAJOR`. Descriptors are Tier 2 (target layout, handed to setters once); TS never writes one — it uses setters, `_set_ext_json` and `anira_em_*_init`. How TS learns layouts: enum values, status codes and `ANIRA_ABI_VERSION` come from `web/src/abi/enums.ts` generated by `tools/abi/scan_header.py` from `abi/enums.h`, `abi/status.h`, `abi/version.h`; `sizeof`/`offsetof` of the Tier-1 PODs come from `web/src/abi/layout.ts` emitted by the layout executable run under node; `anira_sizeof(anira_struct_id)` exists for allocators that cannot see the header. `_Static_assert`s live in `test/abi/test_layout.c`, not in the ABI headers (cffi-parseable headers).

**Why.** Layout identity removes a whole class of per-target drift and lets the worklet read `anira_stage_ctx`/`anira_tensor` with one offset table; the packed dtype keeps every RT and control signature scalar-only; committing the table as data is what stops a well-meaning relayout commit from editing its own assertions.

**Plan impact.** §1 (`DType` defined: `anira_dtype`; `k_max_rank` → `ANIRA_MAX_RANK`), §2 (`k_dynamic`/`k_unbounded` → `ANIRA_DYNAMIC`/`ANIRA_UNBOUNDED`, `Ratio` → two `int64_t`), §4/§5 (`num_threads`, `anchor` sentinels), §7 (`Backend::OrtWebGpu` etc. get numbers).

### H. Runtime data: tensor, sync token, frame

**Decision.** `anira_tensor` is plan:60-77 with vendor typedefs replaced by their wire width (Vulkan non-dispatchable handles `uint64_t`, object pointers `void*` through `ANIRA_PTR`), `dtype` packed, `ndim`/`flags`/`domain` `uint32_t`, and the field order `domain, dtype, ndim, flags, shape[8], strides[8], byte_offset, handle, manager_ctx, release, acquire` (216 bytes, align 8, every target). `anira_memory_handle` keeps plan:22-39's arms plus `uint64_t raw[3]`; `anira_sync_token` is `{uint32_t kind; uint32_t flags; union {...; uint64_t raw[2];} u;}` (24 bytes). Factories are C functions filling caller memory, one per plan:102 arm: `anira_tensor_init_host(t, data, dtype, ndim, shape)`, `_init_pinned`, `_init_cuda(t, ptr, device, cuda_event, dtype, ndim, shape)`, `_init_gl_buffer`, `_init_vulkan`, `_init_opaque_fd`, `_init_wgpu_buffer`, `_init_dmabuf`, and `anira_tensor_init_dlpack(t, void* dl_managed_tensor_versioned)` declared unconditionally with `void*` (the DLPack deleter is wired into `release`/`manager_ctx`); `_init_metal`, `_init_iosurface`, `_init_ahardwarebuffer`, `_init_d3d12` are declared in `abi/draft/tensor_platform.h` until their platform column is measured (plan:95, "no row exists without a measurement"). All factories are `ANIRA_NONBLOCKING` (pure field fills; they zero the struct first so `ANIRA_PTR` high bits are defined). Accessors for JS and for stages, all `[callback-safe] ANIRA_NONBLOCKING`: `anira_tensor_data_f32(t)` (Host domain, honours `byte_offset`, NULL otherwise), `size_t anira_tensor_num_elements(t)`, `size_t anira_tensor_extent(t, axis)` (runtime extents are counts, never `ANIRA_DYNAMIC`; the raw `int64_t shape[]` stays readable through `layout.ts`), `anira_sizeof(id)`. `anira_sync_token_reset(tok)` closes an owned fd; `anira_sync_token_dup(src, out)` duplicates one (§E). `anira_machine_byte_image_bytes(m, elements, dtype)` is the byte-image rule (plan:585). **`anira_stage_ctx.model_inputs/model_outputs` are (re)filled per call**: anira keeps one preallocated `anira_tensor` array per pooled struct (N × 216 B) and re-points it on the calling thread before every `pre_process`/`before_inference` (inputs) and `after_inference`/`post_process` (outputs) with `anira_tensor_init_host` (NB), because LibTorch and TFLite `swap_data` the struct's memory with the engine's scratch on every inference (`src/backends/LibTorchProcessor.cpp:174-176`, `src/backends/TFLiteProcessor.cpp:146-148`) and the struct a call sees is chosen per call (`Context.cpp:968-973`) — nothing about a tensor descriptor is cached across calls, by anira or by compat (§K). `anira_frame` is **not** in the v3.0.0 header (deviation from plan:116 "declared here"): freezing a union nobody has measured is the one ABI mistake a minor cannot correct; its domain/container values are reserved in `enums.h` and it arrives as `abi/draft/frame.h` with `submit_frame`, additive under major 3. POD-by-pointer on RT paths: `anira_tensor`, `anira_sync_token`, `anira_stage_ctx`; opaque: rings; tickets are integers; everything else handles.

**Decision.** Exact signatures are in §3. The load-bearing choices:
- `anira_machine_create(mc, &m, err)` probes and validates; `anira_machine_capabilities(m)` returns a machine-owned `const anira_capabilities*` (refreshed by `anira_machine_probe(m, force, err)`); capabilities enumerate backends, domains, extension kinds and edges with the enumeration convention of §C (stride-explicit for `edges`); `anira_capabilities_edges` returns `{from, to, class, rung, available, reason}` rows (plan:392, never a bool) and `anira_capabilities_edge(caps, from, to, &info)` queries one. `anira_enabled_backends(count, out)` needs no machine (replaces `ContextConfig::m_enabled_backends` and the web's `get_inference_backend_onnx()`). `anira_machine_destroy` per §E: invalidates the handle, joins nothing.

Static tensors: **anira materialises them itself** — Static inputs set through `anira_handler_set_input/set_static_input` are copied into `model_inputs` before any stage's `pre_process` runs, and Static outputs are copied out of `model_outputs` after `post_process`, independent of the stage (v2 did this inside the default `PrePostProcessor`, `src/PrePostProcessor.cpp:12-30, 57-64, 87-92`; in v3 the store is the handler's and no stage can reach it otherwise, since `anira_stage_ctx` is a frozen 56-byte POD without a handler pointer).
- Runtime selection: `anira_handler_set_inference_backend`/`get_inference_backend`, `set_model`/`get_model` are relaxed atomic stores as `src/scheduler/InferenceManager.cpp:36-38` does today, `[thread-safe] ANIRA_NONBLOCKING`, never planning (plan:496-501). `set_model` **stores the request only**; a Stateful switch's stream-state clear (`SessionElement::clear()`-class work on rings and the struct pool, which must run on the session's driving thread, `Context.cpp:1180-1186`, `SessionElement.cpp:63-72`) executes at the next Hard entry on the driver thread, or at the next job boundary on the inference thread under Async — the setter itself never touches a ring.
- Hard entries: the three `process` overloads, two `push_data`, two non-blocking `pop_data`, `reset`, `get_latency`, `get_latencies`, `get_available_samples`, `set_input`/`get_output` map one-to-one onto `include/anira/InferenceHandler.h:177-452`, all `ANIRA_NONBLOCKING` and **none of them waits**. The waiting behaviour v2 keeps inside `process()` when `blocking_ratio > 0` (`InferenceManager.cpp:59-73` → `try_acquire_until`, `Context.cpp:916-923`) and inside every Hard entry under `set_non_realtime` (`wait_for_completion`, `Context.cpp:948-956`) moves to a **`_wait` twin family that is not `ANIRA_NONBLOCKING`**: `anira_handler_process_wait`, `process_separate_wait`, `process_multi_wait`, `pop_data_wait`, `pop_data_multi_wait`, each with `double timeout_ms` (`>= 0` explicit; `ANIRA_WAIT_CONTRACT = -2.0` = `wait_ratio × block duration`, v2's `blocking_ratio` wait; `ANIRA_WAIT_FOREVER = -1.0` = v2's `set_non_realtime` behaviour), tagged `[audio-thread or any-thread, blocking]`; with `wait_ratio > 0` they wait on the semaphore, with `wait_ratio == 0` they poll the done atomic with 1 ms sleeps (v2 `wait_for_completion`), and they return 0 / `ANIRA_ERROR_INVALID_STATE` at once when no inference thread is active (v2 refuses `set_non_realtime` without threads, `InferenceManager.cpp:286-303`). `anira_handler_set_non_realtime` is **not a C entry**; `compat/v2.hpp` implements `v2::InferenceHandler::set_non_realtime(bool)` as a wrapper-side flag that routes the v2 overloads to the `_wait` twins with `ANIRA_WAIT_FOREVER`, and routes them to `ANIRA_WAIT_CONTRACT` when the legacy contract carries `blocking_ratio > 0` — v2-identical from the compat layer, including the latency figure (`get_latency` reports the v2 arithmetic with the wait credit; a host that calls the NB `process` on a `wait_ratio > 0` handler gets the same latency figure and more `on_miss` events). Forced changes: the multi variants write counts into the caller's in/out `num_out` instead of returning a handler-owned `size_t*` (`InferenceHandler.h:229-232,462`, which leaked libc++ layout into TS, `InferenceHandler.ts:201-212`); `tensor_index` is `uint32_t`; `anira_handler_get_available_samples` takes a non-const handler and is `[driver-thread]` because it forwards to `InferenceManager::get_available_samples`, which runs `collect_completed` and therefore the stage's `post_process` (`InferenceManager.cpp:267-276`). Latency vector: index-aligned with the output list, 0 for Static outputs (tree semantics, `InferenceHandler.h:357-360`; plan:456's "never enters the vector" is dropped — a C array indexed by slot is the only representation that cannot misalign). Calling a Hard entry on an Async handler returns 0 / `ANIRA_ERROR_WRONG_CONTRACT`, records it in `rt_error`, logs once through the RT queue; plan:313's type-level coupling is enforced by `anira.hpp`'s types and at runtime here.
- Async entries (M3): `allocate_input/allocate_output(h, slot, domain, &tensor, err)` and `free_tensor(h, tensor)` (§E), `bind_output(h, slot, anira_tensor*, err)` (non-const: owning tokens move), `submit(h, anira_tensor* inputs, num_inputs, opts_or_NULL, deadline_ms, &ticket)` `[thread-safe] ANIRA_NONBLOCKING` (a render loop with a 33 ms deadline must not be the thread that allocates; owning `acquire` tokens move into the slot, §E), `poll(h)`, `ticket_status(h, t)` `ANIRA_NONBLOCKING`, `ticket_wait(h, t, timeout_ms)`, `ticket_input_released/output_ready(h, t, i, &token)` (views, §E), `ticket_error(h, t, err)`, `ticket_release(h, t)`.

### K. Custom stages, rings, legacy `PrePostProcessor`

**Decision.** The v2 hooks (`include/anira/PrePostProcessor.h:83-143`) become one host-domain stage descriptor; ring buffers stay inside anira (the RingChunker's storage, plan:640, `thl::core::RingBuffer<float>` behind `SessionElement::m_send_buffer/m_receive_buffer`, `include/anira/scheduler/SessionElement.h:203-205`) and cross only as opaque `anira_ring*` handles with block accessors — a live view over the ring is impossible because `thl::core::RingBuffer` stores positions as `std::vector<size_t>` and `m_is_full` as `std::vector<bool>` (`tanh-lib/include/tanh/core/RingBuffer.h:250-254`). `anira_stage_ctx` is a fixed-layout Tier-1 POD (56 bytes, no `struct_size`, versioned by ABI major like every RT struct) living on anira's stack for the duration of the callback: `{phase, backend, variant, num_inputs, num_outputs, reserved, input_rings, model_inputs, model_outputs, output_rings}`, its tensor arrays re-pointed per call (§H); the worklet reads it with two `HEAPU32` loads from `layout.ts` and makes one `_anira_ring_pop_windows` call per block — the same single crossing `anira-web-example/src/guitar-lstm/audio-worklet.ts:29-48` has today. ### L. The C++ wrapper

**Decision.** `include/anira/anira.hpp`, `namespace anira`, header-only, C++20 (as the library, `CMakeLists.txt:123`), over `anira.h` only, declared not ABI-stable in its first comment (Dawn `webgpu_cpp.h` rule); nothing in it is exported from libanira, which `anira_exports` proves. Class list and signatures in §3.3. Errors: `anira::Error{anira_status status; std::string message}` thrown by control paths on `ANIRA_FAILED(s)`; `#define ANIRA_CXX_NO_EXCEPTIONS` makes every throwing call return `[[nodiscard]] anira::Result<T>` (`std::expected`-shaped: `{T value; anira_error error;}`, value-initialised — legal because `anira_error` is frozen), never `abort()` (a plugin must not abort the host). RT methods are `noexcept` `ANIRA_NONBLOCKING` inline forwarders in both modes; the `_wait` twins are plain `noexcept`. Manual init: `#define ANIRA_CXX_MANUAL_INIT` routes every call through `anira::detail::api()`, a struct of `PFN_anira_*` pointers filled by `anira::init_api(void* (*loader)(const char*))` or `anira::init_api_from(void* dl_handle)`, resolved lazily so a missing newer function throws `anira::Error{ANIRA_ERROR_NOT_SUPPORTED, "anira_x requires ABI 3.N"}`; `#define ANIRA_NO_PROTOTYPES` makes `anira.h` emit only `PFN_anira_*` typedefs (Vulkan `VK_NO_PROTOTYPES`). Default mode calls the C functions directly, so the driver thread pays no indirection. `anira::Contract = std::variant<anira::Hard, anira::Async>` survives verbatim; `anira::Hard`/`Async` are plain aggregates with designated-initialiser support (`Hard` gains `double wait_ratio = 0`) that mint an `anira_contract` at `prepare`. `stage::Custom(std::shared_ptr<Stage>)` heap-allocates one control block holding the `shared_ptr`, stores it in `user_data` and deletes it in `release` — sound because `release` fires exactly once (§E). Type-level Hard/Async coupling (plan:313) is documented, not enforced by types, since the C layer already returns `ANIRA_ERROR_WRONG_CONTRACT`. `compat/v2.hpp`: `anira::v2::InferenceConfig(std::vector<ModelData>, std::vector<TensorShape>, ProcessingSpec, float max_inference_time, unsigned warm_up, bool session_exclusive, float blocking_ratio, unsigned num_parallel)`, `v2::ContextConfig(num_threads, wait_strategy, log_level)`, `v2::HostConfig(buffer_size, sample_rate, allow_smaller, tensor_index, tensor_is_input)`, `v2::InferenceHandler(pp, cfg, ctx)` with the v2 `process/push_data/pop_data` overloads routed per §J and `set_non_realtime(bool)` as a wrapper flag, `v2::JsonConfigLoader` with `get_context_config()/get_inference_config()` (the plan's `JsonConfigLoader::context` never existed, `include/anira/utils/JsonConfigLoader.h:14-18`), `v2::InferenceBackend::ONNX` = `ANIRA_BACKEND_ONNXRUNTIME_CPU` — constructor-level shims, one minor cycle, each `[[deprecated]]`.

**Why.** ORT's `onnxruntime_cxx_api.h` shape is proven; `Result<T>` is the only no-exceptions mode acceptable in a plugin; constructor-level shims are the difference between a one-line include change and a construction-time rewrite for a v2 JUCE processor in the week the owner does M1–M3.

**Plan impact.** §6 and §9 quote `anira.hpp` (rewritten sketches in §3.3); §10 "Mechanical" paragraph names `compat/v2.hpp`.

Embedding — **tanh_core's objects are absorbed into libanira**. tanh-lib stays a `FetchContent` subtree at its tag (`GIT_TAG v0.1.0`, `CMakeLists.txt:227-237`), its own CMake runs (`tanh_apply_symbol_policy(tanh_core EXPORT_PREFIX TANH)` + `NAMESPACE thl`, `tanh-lib/CMakeLists.txt:508-509`) and the same-tag warning (`tanh-tooling/cmake/modules-version.cmake:14-23`) stays alive; compiling tanh's TUs directly is rejected. The shape (anira-local, ~15 lines): `BUILD_SHARED_LIBS` is scoped `OFF` around `FetchContent_MakeAvailable(tanh-lib)` so `tanh_core` is a static archive compiled hidden with `TANH_STATIC` PUBLIC (`symbol-policy.cmake:110-115`); `target_sources(anira PRIVATE $<TARGET_OBJECTS:tanh_core>)` puts its five objects (`tanh-lib/CMakeLists.txt:108-114`) into `libanira.{a,so}`; `target_link_libraries(anira PRIVATE $<BUILD_INTERFACE:tanh_core> $<BUILD_INTERFACE:concurrentqueue> $<BUILD_INTERFACE:nlohmann_json::nlohmann_json>)` carries include directories and defines (`TANH_STATIC`, `THL_PLATFORM_*`) at build time and evaluates to nothing in the install export, so `install(EXPORT aniraTargets)` (`cmake/install.cmake:359-363`) never demands `tanh_core` in an export set — the reason today's tree installs `libtanh_core.a` and exports `concurrentqueue nlohmann_json` (`CMakeLists.txt:225`, `install.cmake:49-57`) disappears; tanh_core's one PRIVATE system link (`log` on Android, `tanh-lib/CMakeLists.txt:153`) is repeated on anira. `tanh_hidden_archive_link_items` (`symbol-policy.cmake:219-231`, a configure-time basename over a path, unusable with `$<TARGET_FILE:tanh_core>`) is no longer needed for tanh and stays for the engine archives. Why this also closes the two-copies hazard: anira's TUs see `TANH_STATIC`, so `TANH_API` is empty and, under `-fvisibility=hidden`, every reference from anira to `thl::Logger::set_callback`, `thl::Logger::rt::Queue`, `thl::core::Thread` is an **STV_HIDDEN undefined reference**, which the static linker may satisfy only from a relocatable object — a `libtanh_core.so` listed earlier on a plugin's link line (a tanh-lab plugin using `tanh::State`) cannot interpose it on ELF or Mach-O regardless of link order, and the objects that satisfy it are the ones inside `libanira.a`. On PE that guarantee does not exist (no visibility on undefined references), so the rule "list `anira::anira` before `tanh::Core`" is documented for Windows and `test/install/consumer_tanh_first` (links a shared `tanh::Core` first, then `anira::anira`, and checks with `nm`/`dumpbin` that the module binds `thl` locally) runs on the ELF and Mach-O install legs. A shared `libanira.so.3` carries tanh_core under `local: *` of its version script; a static `libanira.a` carries it hidden; on Mach-O the plugin's `-exported_symbols_list` does the same job. `concurrentqueue` and `nlohmann_json` are header-only, `SYSTEM`, build-interface only. `THL_LOG_COMPILED_MAX_LEVEL` is a per-`$<CONFIG>` PUBLIC define of tanh_core (`tanh-lib/CMakeLists.txt:134-137`, `1` in Release) consumed only in `Logger.cpp:46-62`: anira sets tanh-lib's `TANH_LOG_COMPILED_MAX_LEVEL` option to `4` as a plain variable before the fetch (tanh-lab/tanh-lib#37), so `anira_log_desc.level` means the same thing in every build type and the v2-JSON `ANIRA_LOG_WARNING` reaches a Release sink.

Log design: anira keeps a **private** `thl::Logger` (the copy inside libanira) and installs **one trampoline** on it (`thl::Logger::set_callback`, once per core) that fans out to a per-copy sink registry `{callback, user_data, level, in_flight}` with one entry per machine that set a sink; the platform sink is disabled when `ANIRA_LOG_FLAG_DISABLE_PLATFORM_SINK` is set by any live machine — the plan's sentence "anira never calls `set_config`" (plan:415) was about the application's logger, which is now a different, invisible copy. `anira_machine_destroy` unregisters its entry and blocks until that entry's in-flight count is zero (an entry is dispatched from a copy outside `thl`'s mutex, `tanh-lib/src/core/Logger.cpp:466-472, 501-505`, so a clear alone would not suffice); a destroy issued from inside a sink (the drain thread, detected by `DrainThread::is_current_thread()`) is refused with `ANIRA_LOG_ERROR`. Two machines in one copy (two instances of one plugin in one DSO) therefore each keep their own sink and neither is called after its destroy. `anira_log_record` is a projection of `thl::Logger::LogRecord` (`tanh-lib/include/tanh/core/Logger.h:36-44`): level mapped anira `DEBUG 0..ERROR 3` ↔ thl `Error 1..Debug 4` (`include/anira/utils/Logger.h:65-73`), group strings verbatim (`Logger.h:43-53`), `flags & ANIRA_LOG_RECORD_REALTIME` for records that came through the RT queue (256-byte messages, `tanh-lib Logger.h:197-212`), `dropped_before` = the queue's drop counter. RT path unchanged: `ANIRA_LOG_RT_*` → the core-owned `thl::Logger::rt::Queue` (capacity clamp `[64, 65536]`, `Context.cpp:259-286`) drained by the private `DrainThread` "anira-log" at `ThreadPriority::Low` (`ANIRA_LOG_DRAIN_THREAD`, `Context.cpp:287-296`) or by `anira_drain_log` (`MANUAL`, forced on Wasm); `anira_log_rt` writes into the same queue. Sinks run on the threads listed in §F, never the driver thread.

`Thread`, `RCU`, `Dispatcher`, `LockFreeQueue`: internal. `thl::RCU<T>` (namespace `thl`, `tanh-lib/include/tanh/core/threading/RCU.h:19,81`, not `thl::core` as plan:949 says) is M5's selection candidate **natively only**: it keys reader identity on `static thread_local rcu_thread_state()` (`tanh-lib/src/core/RCU.cpp:24-29`), which the Wasm build cannot honour (§M); on Wasm selection stays the relaxed-atomic index of `InferenceManager.cpp:36-38`, which is sufficient with one pump instance. Two copies of tanh_core in one process (two plugins, or plugin + host using tanh-lib): each owns its `g_runtime_level`, `state()`, `default_queue()`, `atexit` hook, `rcu_thread_state()` (`tanh-lib/src/core/Logger.cpp:73-79,112-132,380-384,546-553`); with the objects absorbed and hidden nothing of either copy is in a dynamic symbol table and (ELF/Mach-O) nothing can bind across; the only visible effect is two "anira-log" drain threads. Pin rule: anira's tanh-lib tag may move freely; anira and the fetched tanh-lib must carry the same tanh-tooling release in `cmake/tanh/` (0.1.5 today) — a tooling bump is a two-repo PR pair. tanh-lib gets no C ABI. Installed package: `include/anira/{anira.h, anira_all.h, abi/*.h, abi/draft/*.h, anira_em.h, anira.hpp, compat/v2.hpp}` (explicit file list), `libanira.{so.3.x.y,3.dylib,a}`/`anira-3.dll`+`anira-3.lib`, `include/anira-backends/<engine>/` and engine libraries unchanged, `lib/cmake/anira/{aniraConfig.cmake (engines only), aniraConfigVersion.cmake (SameMajorVersion), aniraTargets.cmake, aniraBackendTargets.cmake, tanh/*.cmake}`; no `include/tanh`, no `libtanh_core`, no concurrentqueue, no nlohmann, no benchmark headers.

**Why.** One copy of anira = one self-contained world (hidden visibility, `-fno-gnu-unique`, private pool, private logger, absorbed tanh objects); this is what makes two plugins with two anira versions beside a host that ships its own ONNX Runtime — or its own tanh-lib — safe, and it uses only modules that exist (constraint 5) plus fifteen anira-local lines.

### P. Migration and roadmap placement

**Decision.** M0 ships from `main` as **v2.3.0** with a CHANGELOG preamble stating that the 2.x line never carried a binary-compatibility promise (no ABI gate, `AnyNewerVersion` package, `USE_*`-shaped layouts, `sizeof(HostConfig)` and `Buffer` layout changed, `CHANGELOG.md:8-51,33`), that its eight `**Breaking:**` entries are source renames with deprecated forwards, and that v3.0.0 is the first release that promises anything about its ABI; `v3.0.0-alpha.0` is offered as the owner's alternative (§7), not the recommendation, because the tag is due tomorrow from another developer and the name is keyed into the backends release (`cmake/backends.cmake:55-58`), the npm 2.x line and every "v2 parity" reference. The only M0 code change is the `unloadtest_*` rename.

"ABI 0 / unstable" before the freeze: the header exists in full, `ANIRA_ABI_MAJOR` is 0, `ANIRA_ABI_MINOR` is the alpha/beta ordinal, `anira_check_abi` demands an exact match, gates 1, 3, 4, 5, 6 fail the build once online, gate 2 reports, the CHANGELOG prefixes header changes with `**ABI (unstable):**`, npm publishes under `next` (`publish_web.yml` already does for prerelease tags). v2 C++ API during the alphas: **alpha.1 is the configuration layer only** — the M1 headers (`abi/{export,version,build_info,status,enums,config,log}.h`) are included per file, the v2 classes stay public and exported, `include/anira/anira.h` stays the C++ umbrella, `USE_*` stay PUBLIC, and the plan's translator feeds the v2 engine from the v3 configuration; nothing that needs a handler exists at M1 because `anira_machine`/`anira_pipeline`/`anira_handler` freeze at M2. From **alpha.2** the v2 classes are compiled as the engine behind the C entries but are neither installed nor exported (`SYMBOL "anira_*"` only, internal `ANIRA_API` empty), the C umbrella is `include/anira/anira.h`, the v2 suite runs through `anira.hpp`/`compat/v2.hpp`, the JUCE/CLAP examples build against `anira.hpp`, and `consumer_c` runs the raw-C §9 sketch. Per-milestone deliverables and efforts are in §6.

§10 rewritten in one paragraph: *v3.0.0 is a major version whose one-time source break introduces the versioned C ABI (`anira/anira.h`, `ANIRA_ABI_MAJOR 3`) that does not break thereafter; `anira.hpp` and `compat/v2.hpp` are source-level conveniences with no binary promise. Behaviour changes for direct v3 callers, none for `compat/v2.hpp` users: the `ANIRA_NONBLOCKING` `process` never waits — v2's `blocking_ratio` wait and `set_non_realtime` are the `_wait` twins (`ANIRA_WAIT_CONTRACT`, `ANIRA_WAIT_FOREVER`); the JSON loader no longer drops unknown keys or absent backends (`prepare` fails by name); `anira_shutdown` refuses while machines live. ### R. What anira borrows from CLAP, and what it does not

Applied (each is a decision above, not a listing):
1. **Per-slot thread tags** (`clap/include/clap/plugin.h:41-110`, `ext/thread-check.h:37-41` "[audio-thread] functions ARE NOT CONCURRENT") — every declaration in §3 carries one tag from the vocabulary in §4, which extends CLAP's `[main-thread]`/`[driver-thread]`/`[thread-safe]` with `[inference-thread]`, `[drain-thread]`, `[callback-safe]` (additive), `[any-thread, blocking]`, `[main-thread & !loader-lock]`, `[main-thread & !prepared]`, `[main-thread & prepared]`; "not concurrent" holds per handler, not per machine (deviation: anira has more thread roles than CLAP's two).
2. **Version-first host-provided vtables with the user pointer second** (`clap_host.clap_version`, `host_data`, `host.h:10-12`; `clap_plugin.plugin_data`, `plugin.h:42-44`) — `anira_stage_desc`, `anira_backend_desc`, `anira_log_desc` are `{struct_size, abi_version, user_data, ...}`; deviation: one packed `uint32_t` instead of `{major, minor, revision}` because every other version in the header is packed and TS writes one field.
3. **Compat macros** (`CLAP_ABI` `__cdecl` on Windows, `private/macros.h:20-26`; C99+C++ one header, `private/std.h:5-16`) — `ANIRA_CALL`, `ANIRA_INIT`, `extern "C"` guards, C11-and-C++17 compile test.
4. **The `init`/`deinit` refcount rule** (`entry.h:34-60`) — applied **per DSO**, as CLAP means it: the plugin's `clap_entry` counts its own `init`/`deinit`; `anira_shutdown` is idempotent, never creates the core, and refuses while any machine or handler exists in the copy, which is what protects a shared `libanira.so.3` between two clients — a rule CLAP does not need because a CLAP DSO is never shared. `anira_release_core_if_idle` is the last step.
5. **String ids with a revision and a draft folder** (`conventions/extension-id.md:3-22`; `clap.h` vs `all.h`) — extension kinds are strings with a `version` field in `anira_ext_header` and the registry key is `(kind, version)` (deviation: revision as a field, not a `/REV` suffix, because the kind doubles as the JSON key, plan:164); `include/anira/abi/draft/` + `anira_all.h` carry unmeasured surfaces with their own baselines; promotion never renames; no `_COMPAT` ids ever; third-party reverse-URI kinds reserved, post-3.0.
6. **Size-first records for what the host enumerates** (`events.h:11-17`) — `anira_edge_info`, `anira_plan_slot`, `anira_plan_ext` are `struct_size`-first and walked by stride/count; rows with pointers are valid for the call only (the sysex rule, `events.h:311-326`). Deviation: `anira_log_record` and `anira_error` are frozen Tier-1 PODs, not size-first, because one is read per drained record and the other is value-initialised by `Result<T>`.
7. **Allocation confined to activation** (`plugin.h:61`, "Once activated the latency ... must remain constant") — restated as anira's promise: **no allocation after `prepare` on any `[driver-thread]`/`[inference-thread]` path** (gate 6); `anira_handler_create` loads models, `allocate_*` allocates by name, `anira_machine_create` probes — all `[main-thread]`; `get_latency` is valid from `prepare` on; a `prepare` while processing is a contract error.
8. **Render mode ↔ contract kind** (`ext/render.h`) — `anira_contract_kind` at `prepare` is the CLAP `set(REALTIME|OFFLINE)`; `ANIRA_ERROR_WRONG_CONTRACT` is clap-helpers' "OFFLINE refused when hard-realtime".
9. **Log severities** (`ext/log.h:18-21` `HOST_MISBEHAVING`/`PLUGIN_MISBEHAVING`) — deviation: the four v2 levels stay; a contract violation detected by the wrapper or the C layer is a record with `ANIRA_LOG_RECORD_CONTRACT_VIOLATION` set, so the level filter's "most verbose wins" ordering is unchanged.
10. **`clap_id`/`CLAP_INVALID_ID` and caller-owned text buffers** (`id.h:6-8`, `ext/params.h:258-293`) — `uint32_t` indices, `ANIRA_TICKET_INVALID = 0`, `(buf, cap, *out_len)` for text.

Deliberately not borrowed: string-keyed `get_extension` near the driver thread (everything string-keyed resolves at `prepare`; `anira_get_proc_address` covers "functions not all builds provide"); the plugin-side vtable as the library boundary (library entry points are flat functions; vtables are used only for host-provided services and are not callable from JS otherwise); `bool` as the only error channel; bundling the process call into one struct (the hot path is frozen at `float* const*`); host-pumped main-thread machinery (`request_callback`, timer-support, posix-fd-support — anira has no event loop, only `anira_handler_poll`); fixed 256-byte name arrays in hot structs (names live on `anira_tensor_spec` only); `clap_version_is_compatible = major >= 1` (anira majors may break; `anira_check_abi` tests major equality); blocking `thread-pool.request_exec` (`ext/thread-pool.h:35-39,52-61` — a fork-join inside `process()`; anira's threads are long-lived `anira_inference_thread` loops and a host-provided thread-provider vtable is deferred, see §7); `CLAP_EXPORT` export-only macro (anira needs import/export and an Emscripten branch); convention-only stability (CLAP ships no checker; anira ships six gates).

## 3. The header sketch

Ownership notes are the comments. `_Static_assert`s are in `test/abi/test_layout.c`, not here.

## 7. Open decisions for the owner

1. **M0 tag name: `v2.3.0` (recommended) or `v3.0.0-alpha.0`.** The branch carries eight `**Breaking:**` entries and two layout changes (`CHANGELOG.md:8-51,33`), so `v2.3.0` is honest only with the preamble that 2.x never promised binary compatibility. Consequence of `v2.3.0`: "v2 parity" keeps its name, the backends release `v2.3.0` and the npm 2.x line stay aligned, plugin authors get a pin; consequence of `alpha.0`: `on_tag.yml` artefact names, the backends-release vocabulary and every "v2 parity" reference change the day before the other developer tags, and `cmake/version.cmake` must land in M0.
2. **Browser WebGPU out of v3.0.0 (recommended), or a JSPI-linked second module variant at M6.** The synchronous Worker pump cannot observe a GPU completion (§M); the recommended path keeps the header unchanged and adds an asynchronous backend contract post-3.0 (additive: an `anira_backend_desc` tail slot + completion callback); the JSPI variant ships two modules from one header and needs an ORT wasm archive built for JSPI, which the backends release does not carry.
3. **Ticket width: `uint32_t` slot16|gen16 (recommended) or `uint64_t`.** `uint32_t` keeps `bigint` off every TS Async call; 65,535 slots and a 16-bit generation are ample for `lanes * max_in_flight + 8`; a `uint64_t` would only buy ABA margin the generation already provides.
4. **Layout identity via `ANIRA_PTR` (recommended) or native pointers.** Identity gives one `layout.ts` and one offset table on every target at the cost of one cast per producer field and the "zero the struct first" rule; native pointers give 216/208 sizes and two tables.
5. **`anira_dtype` as packed `uint32_t` (recommended) or `const anira_dtype*`.** Packed keeps every signature scalar; the bytes equal `DLDataType`, so `from_dlpack` is a `memcpy`.
6. **`anira.hpp` requires C++20 (recommended); `anira.h` compiles as C11 and C++17.** A C++17 host uses the C header or a subset; designated initialisers in the §9 sketches and `std::span` are the reason.
7. **tanh-tooling v0.1.6 (`ALLOW_PREFIXES`, `EXPECT_SYMBOLS`, `_tanh_exports` as a function, Wasm branch, prerelease-aware `git-version`, `tanh_add_abi_check`; tanh-lib `TANH_LOG_COMPILED_MAX_LEVEL` option) after v3.0.0 (recommended) or bundled with M2.** After: the M1–M3 window is the scarce resource and the anira-local scripts total ~80 lines; bundled: one tag, two re-pins, in the busiest week.
8. **`ANIRA_LOG_FLAG_DISABLE_PLATFORM_SINK` default off (recommended: the platform sink stays on even with a sink callback, v2 behaviour) or on.** Off keeps today's console output for hosts that only add a callback; on avoids duplicate lines in DAWs that show stderr.
9. **Host thread-provider vtable (CLAP `thread-pool` idea): deferred (recommended).** `num_threads = 0` + `anira_inference_thread_*` already lets a host bring its threads; a provider that spawns threads *for* anira is additive later and would need a `[thread-safe]` spawn/join contract not yet measured.
10. **Wasm exception mode: keep JS-based catching (`-sNO_DISABLE_EXCEPTION_CATCHING`, recommended) or move to `-fwasm-exceptions`.** The firewall needs one of the two; native wasm EH is smaller and faster but requires the ORT wasm archive in the backends release to be built with it.
11. **Two "anira-log" drain threads when a host also links tanh-lib: accept (recommended).** A merge would require tanh-lib to become a shared dependency again, which is the situation being left.
12. **`anira_frame` absent from the 3.0.0 header (recommended) vs plan:116's "declared here".** Reserve values now, ship the struct with `submit_frame` in `abi/draft/frame.h`; a frozen unmeasured union cannot be corrected in a minor.
13. **Unmeasured platform arms in `abi/draft/tensor_platform.h` with `symbols-draft.txt` (recommended) or in `abi/tensor.h` outside the promise by comment.** The draft folder is the CLAP rule made mechanical: promotion moves a name between baselines, never renames it.
14. **GPU CI hardware for M4** (unchanged from the plan): the C surface for M4 is additive, so its absence cannot break the M6 freeze — it only leaves enum values unconsumed on CI builds. Recommendation: ship the probe cache as a fixture so CPU-only CI exercises the planner against a recorded registry.
15. **Where `PlanPolicy` lives: on the contract handle via `set_edge_cost` (recommended) or a separate handle.** The contract file carries `edge_cost` (plan:750) and `prepare` takes one object; a second parameter would exist only to mirror the plan's `PlanPolicy{}` spelling, which `anira.hpp` keeps as the `edge_cost` member of `Hard`/`Async`.
16. **Third-party extension kinds post-3.0 (recommended) or `anira_register_ext_kind` + a payload accessor in v3.0.0.** Post-3.0 is additive and no external consumer exists; in-3.0 costs ~1 day inside the M2 week.
